# AFH03 与 USB 同步双目乒乓球发球测量方案

版本：2026-09-29 方案稿。申报定位：2026 FPGA 创新设计赛道**自主命题**。准备周期：2026-09-29 至 2026-10-28。

## 1 先说清楚这条路线

一台已完成双目同步的 USB 摄像头模组经 AFH03 的 RK3576J Type-C 高速 USB 口，把同一次曝光的左右图像送到 RK3576J。RK 保存双目原图，生成较小的灰度搜索图，经板内 PCIe 2.0×1 交给安路 PH1A90SEG324 FPGA。FPGA 每帧完成双路运动搜索、候选筛选及球心硬件测量；RK 根据候选从同帧原图取双目局部图，进行标定映射和三角测量；NPU 识别球、手和球拍，辅助重捕获与事件判断。最终输出球的三维轨迹、抛球高度、方向、离手和触拍证据。

摄像头采购目标为**左右各 1920×1080、同时 60 fps，光学基线 150～200 mm**。这是项目设计输入，并非某个已选模组的已验证能力。优先选择双全局快门、硬件同曝光、USB 3.x SuperSpeed、Linux ARM64 可取左右原图的成品模组。球运动和光照会决定实际曝光时间；短曝光配合补光设计。

这条路线的核心不是让图像绕 FPGA 转一圈。FPGA 接收固定格式的左右搜索流，逐帧生成候选；当球进入局部图时，它还完成左右球心的硬件细化与质量计数。RK 的通用处理器负责 USB 协议、缓存、标定坐标变换、三角测量和显示；NPU 处理类别与遮挡。答辩时用同一批帧比较 FPGA 路径与 RK 软件参考路径的候选召回、CPU 占用、处理延迟和资源消耗，依据实测展示 FPGA 的价值。

## 2 竞赛定位和接口事实

安路选题指南的“选题三”把 FPGA 端 MIPI CSI 采集及 JPEG/LZ77 硬件压缩列为基础任务；本版按照用户确定的**自主命题**组织交付，重点展示双目同步测量、FPGA 并行视觉和 RK3576J NPU 协同。[R1] 原有两份 SC130GS MIPI 路线按 2026-09-28 版本归档。

AFH03 厂商手册列出 RK3576J Type-C OTG 高速 USB 信号，以及两路 USB 2.0 Host 口；板内 RK3576J 与 FPGA 通过 PCIe 2.0×1 相连。[R2] 摄像头连接 Type-C 的 USB 3 SuperSpeed 路径，并在 RK 系统中配置为主机模式、确认供电及线缆速率。USB 2.0 Host 口可留给键盘或 U 盘。手册中的 PCIe0 与 USB3 OTG0 是不同信号组，具备同时设计的物理基础；最终以板上设备树、枚举和并发传输记录确认。

USB 连接器名称、镜像配置与实际链路速度需要在采购前用 AFH03 实物确认。选模组时取得供应商的 UVC 描述符或 ARM64 SDK、`v4l2-ctl --list-formats-ext` 输出、左右图像拆分规则、同曝光证明、功耗与供电条件。USB 3 的 5 Gb/s 是物理层速率，具体有效视频吞吐依赖格式和 USB 开销。[R3、R4]

## 3 模组选型清单

| 必核项目 | 采购时要求的证据 | 对本项目的作用 |
| --- | --- | --- |
| 左右各 1080p 60 fps | 同时运行的模式表、像素格式、样例文件及 USB 传输速率 | 确认“60 fps”对应两只相机同时输出 |
| 同步方式 | 共触发或同曝光时序说明、左右帧序号或设备时间戳 | 避免把主机收到数据的时间误作曝光同步 |
| 快门与曝光 | 全局快门传感器型号、手动曝光/增益接口 | 降低快速飞球的形变和拖影 |
| 基线和标定 | 光心间距 150～200 mm、镜头型号、标定文件或标定方法 | 确定测距灵敏度及工作距离视场重叠 |
| USB 与软件 | USB 3.x SuperSpeed、UVC 或 Linux ARM64 SDK、左右原图获取方法 | 接入 RK3576J 并保持图像和帧号可追溯 |
| 供电和安装 | 电流峰值、接口类型、线缆长度、固定支架尺寸 | 核对 AFH03 Type-C 供电与实物机位 |

整机模组即使附带厂商深度算法，本项目仍读取左右图像，让 FPGA 自主完成运动候选和球心硬件测量，并用团队标定结果重建球心。可把厂商深度作为独立参考，但主结果来自本项目处理链。

## 4 理论带宽与存储预算

按每眼 1920×1080、60 fps 计算，左右合计 248.832 百万像素/秒。以下均为**有效像素理论值**，另需计入 USB 协议、图像步幅、内存复制、PCIe 包和 DMA 开销。

| 像素格式或内部流 | 理论数据量 | 设计含义 |
| --- | ---: | --- |
| 双目 GRAY8 原图 | 248.83 MB/s | USB 3 的首选无损灰度目标格式 |
| 双目 YUYV 16 bit | 497.66 MB/s | 接近 USB 3 5 Gb/s 经 8b/10b 编码后的 500 MB/s 上界，作为高风险模式 |
| 双目 RGB24 | 746.50 MB/s | 高于上述 USB 3 单链路编码后上界 |
| FPGA 双路搜索图，各 960×540 GRAY8 60 fps | 62.21 MB/s | RK→FPGA PCIe 主流量；每眼 2 倍缩小 |
| FPGA 双路局部图，各 256×256 GRAY8 60 对/秒 | 7.86 MB/s | 仅在有球候选时传输；此数是每帧均有候选的预算 |
| 搜索图加局部图 | 70.07 MB/s | PCIe H2C 纯载荷上界示例，C2H 为候选和球心元数据 |

USB 3.0／USB 3.2 Gen 1 标称 5 Gb/s；采用 8b/10b 编码时数据位上界约 500 MB/s，实际 USB 视频吞吐更低。[R3] 因此采购优先锁定左右 GRAY8／RAW8 同时 1080p60；若模块只提供 MJPEG，先核对双路 60 fps 和解码负载，再评估球边缘的压缩伪影。USB 2.0 的 480 Mb/s 理论 60 MB/s 与上述无压缩目标相差明显。

PCIe 2.0×1 单方向编码后理论约 500 MB/s。[R5] 70.07 MB/s 是其约 14% 的理论上界，不代表已实现的 DMA 吞吐。RK 侧 8 对 GRAY8 全帧约 33.18 MB，适合用环形缓冲保存候选往返期间的原图；实际占用依据 V4L2 帧步幅与队列深度计算。FPGA 上一对 960×540 搜索图约 1.04 MB，放入板载 256 MB DDR3L；读旧帧和写新帧的纯像素访问约 124.42 MB/s。[R2]

## 5 从相机到三维轨迹的处理步骤

### 5.1 RK 接收和帧配对

A 先用 V4L2/UVC 或模组 SDK 枚举摄像头，保存左右同组帧的分辨率、FourCC、步幅、帧序号、设备时间戳、主机接收时间和曝光设置。单路左右拼接图按厂家定义拆分；双视频节点按设备配对序号关联。模组的“已同步”应体现在共曝光或硬件触发资料中，软件只负责保持对应关系。[R4]

原图留在 RK 内存。RK 用确定的缩小规则生成双路 960×540 GRAY8 搜索图，附 `pair_id`、左右顺序、原图尺寸、裁剪规则和配置版本。第一版可用 CPU 软件参考实现；随后按板上格式支持情况把缩放交给 RGA，并记录其耗时。每对搜索图经 PCIe H2C 进入 FPGA。

### 5.2 FPGA 两级硬件视觉

第一级逐路处理 960×540 搜索图：行缓存支持 3×3 平滑；与同侧上一帧作亮度差；阈值、形态学和连通区域统计形成候选框。两路可以时分共用计算单元，也可各用流水线，选择以 TD 综合时序和资源为准。前一帧和当前帧的 `pair_id` 保持清晰；静止时保留预测窗口与低频全景重检。

第二级由 RK 依据同一 `pair_id` 的候选，从**两张原图**取局部图，按标定映射形成配对的 256×256 灰度 ROI，再经 PCIe 送 FPGA。FPGA 对左右 ROI 做局部阈值/边缘、连通域与质心或圆形轮廓统计，输出左右球心、形状和置信度。这样硬件处理既决定“看哪里”，也提供三角测量所用的像素观测。ROI 内容、坐标变换和球心量化格式由 A、B、C 在首周用黄金样例联合评审；当前文字只定义语义。[R6]

### 5.3 双目标定和三角测量

B 用最终模组、镜头、焦距、工作分辨率和固定机位，拍多角度标定板。OpenCV `stereoCalibrate` 求左右相机关系，`stereoRectify` 与投影矩阵建立共同行坐标；另外用已知球台点建立世界系，建议 X 沿台面横向、Y 沿长度方向、Z 竖直向上，长度单位米。[R6] 标定结果附版本、重投影残差及独立已知点检验。

在校正后的双目中，左右球心横坐标之差为视差 `d`。简化平行相机模型给出 `Z≈f_px×B/d`，其中 `B` 为 0.15～0.20 m 基线，`f_px` 为实际标定得到的像素焦距。深度的一阶敏感度约为 `|ΔZ|≈Z²|Δd|/(f_px B)`。公式说明较大基线通常改善远处视差灵敏度，同时需要保证近处双目共同视场；最终误差还取决于同步、标定、球心、镜头与遮挡。正式程序用完整标定矩阵、左右球心及三角化求世界球心，并给每个观测附质量状态。[R6]

### 5.4 NPU 辅助与发球事件

C 用轻量检测器识别球、手、球拍，优先从 FPGA 候选附近的双目上下文推理；球暂时被手遮挡或目标丢失时扩大搜索并重新识别。初期按 20～30 次/秒设计，RK3576J 上的真实推理速率和并发性能通过 RKNN 记录。AI 输出类别、框、分数、对应 `pair_id` 和模型版本，不承担绝对深度真值。[R7、R8]

B 用有效三维球心拟合上升与下降段；离手依据球手距离、连续向上运动和画面间隙，触拍依据球拍邻近与轨迹速度变化。抛球高度为最高球心 Z 减离手球心 Z。轨迹点区分实测、预测和待复核；临界事件保存左右原图 ROI、时间区间、标定与模型版本。规则辅助提示以 ITTF 发球至少上升 16 cm 的规定为依据，判罚阈值和不确定度由三人评审后确定。[R9]

60 fps 的帧间隔约 16.67 ms。例如离手速度为 2 m/s 时，球在一个帧间隔内可移动约 3.3 cm；因此离手时刻以相邻帧区间和轨迹插值表示，并用独立参考录像评估高度误差。同步精度、曝光时间和标定质量与帧率一起决定测量效果。

## 6 工作安排与验收

A 负责 USB3 摄像头接入、同曝光帧配对、原图环、缩图、PCIe 双向 DMA、FPGA 顶层及回放。B 负责 FPGA 双路搜索和局部球心 RTL、双目标定、三角化、轨迹及事件。C 负责数据规范、球手拍检测模型、RKNN 量化部署、困难场景和独立评价。三人共同采集、基础标注和复核；职责详见同目录的三人分工文档。

第 1 周完成模组证据、AFH03 Type-C SuperSpeed／PCIe 资源核对、文件黄金样例及标定流程。第 2 周完成真实双目帧配对、FPGA 双路候选及静态球三维位置。第 3 周接入局部球心硬件、NPU 模型、真实发球轨迹与证据回放。第 4 周做独立场次、稳定运行、FPGA 启用与软件参考对照，留最后两天修复和演示。每周保留可复现版本。

验收记录分开写“目标”和“实测”：左右完整帧率、曝光同步证据、USB 实际速率和丢帧、PCIe H2C/C2H、FPGA 资源与时序、候选召回、球心和三维误差、NPU 耗时、端到端 P50/P95、有效观测比例。先用已知位置球架和标准动作建立测量基线，再用独立场次评价。60 fps 是整机设计目标；实验数据形成前，报告只展示理论值。
