# C AI 模型训练与部署职责说明

你负责让 RK3576J NPU 在真实发球视频里识别球、手和球拍，处理 FPGA 候选中的身份歧义和遮挡，并输出可追溯到同一曝光对的结果。三维距离以双目几何为主，AI 提供类别和搜索提示。准备周期为 2026-09-29 至 2026-10-28。[R1]

## 从数据到模型

制定双目数据表：`pair_id`、左右原图路径、原始相机帧序号、曝光、USB 像素格式、mode_id、每眼尺寸、标定版本、球/手/拍框、可见性、遮挡类型、事件区间和拍摄场次。A 提供成对原图与回放，B 提供双目标定和球架真值。三人各标自己采集的基础数据，再交叉抽查；你管理规则、冲突处理和训练/验证/独立测试的场次隔离。相邻视频帧归入同一数据组，避免结果受重复画面影响。

先从轻量 YOLOv8n 级检测器训练球、手、拍三类框。优先在 FPGA 候选附近取上下文，目标丢失时扩大搜索。球的连续高频像素位置由 B 的 FPGA 球心流水线给出；你的检测结果帮助确认“这是什么”和“下一步去哪里找”。OV9281 黑白图复制为三通道；两种模式的左右输入、亮度范围、缩放、补边、归一化、坐标逆变换都写成一份训练与板端共用的输入规范。[R2]

补齐明暗、球手交叠、球拍反光、运动模糊和最高点慢运动等场景。报告分别列出球/手/拍召回、误检、重捕获率、FPGA 候选遗漏与检测器补救样本。独立场次评价包含未参与训练的人员、背景和机位扰动。你协助 B 用同帧号、极线与预测位置完成左右身份关联，并整理离手/触拍参考及事件逻辑；距离、高度与规则提示由 B 用几何和量具验证；模型框的准确率与空间测量误差分开汇报。

## 从训练到 RK3576J

先核对 PyTorch 与 ONNX 同图输出，再用 RKNN Toolkit2 为 RK3576 转换。Rockchip Model Zoo 的 YOLOv8 示例可作预处理和后处理参考，实际类别权重来自本项目训练。[R2、R3] 以实际图像做 INT8 校准，记录 Toolkit、Runtime、NPU 驱动和板卡镜像版本。比较浮点、ONNX、RKNN 的类别框和分数，定位量化造成的召回变化。

推理任务带 `pair_id`、左右侧别或双目上下文标记、ROI 在原图的位置、模型与标定版本。初期设计约 20～30 次/秒的检测调用；真实板端同时运行 USB 采集、PCIe、B 的三维程序和界面，再记录排队、预处理、纯推理、后处理和端到端 P50/P95。依据测量结果调整上下文尺寸和调度频率。NPU 检测与 FPGA 每对帧的球心测量并行工作，FPGA 的球心结果仍是三角化的主要像素输入。

## 每周交付

- 第 1 周：数据与标注规范、按场次划分的数据清单、基础模型训练及一次 RKNN 试转换。
- 第 2 周：三类检测首版、静态与动态样例的召回/误检、板端单模型调用。
- 第 3 周：困难场景补训、量化一致性、左右身份/事件辅助，60/100 fps 下与 FPGA 帧对齐。
- 第 4 周：独立测试、输入输出和权重版本清单、NPU 耗时及失效样例；参与整机报告和答辩演示。

你交给 B 的是三类框、分数、原始 `pair_id`、坐标逆变换、模型版本和身份不确定性；交给 A 的是输入格式、队列状态和界面字段。模型权重与原始视频留在本地，仓库保存配置、清单和验证记录。

## 评价与排错的具体做法

先建立少量可逐帧检查的黄金视频，覆盖持球、离手、最高点、触拍和球暂时被挡住。每条标签附 `pair_id` 和左右原图路径。训练集、量化校准集、调参验证集、最终测试集按整段拍摄场次隔开；每次更改类别或标注规则，都重新检查这些固定样例。

模型精度从三类框各自的召回和误检看起，再单独统计 FPGA 有候选但模型认错、FPGA 暂无候选而全景检测找回目标的情形。比较 PyTorch、ONNX、RKNN 时使用同一幅图和同一预处理，先检查张量尺寸、通道顺序、颜色范围、补边和坐标逆变换，再检查量化误差。板端报告把排队、预处理、推理、后处理分开计时，说明 20～30 次/秒设计值与实际值的关系。

给 B 的困难场景清单要能定位到左右图和事件阶段，使他能判断是球心测量、左右匹配还是类别确认的问题。给 A 的版本清单包含模型文件哈希、输入尺寸、量化方式和 Runtime 版本，支持现场复现。
