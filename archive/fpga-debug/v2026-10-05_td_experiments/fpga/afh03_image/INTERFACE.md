# afh03-image-v0.1 内部接口草案

本接口限定在 FPGA 内部单一处理时钟域，供摄像头适配层、图像内核与后续缓存适配层对接。本页定义既有基础内核的内部端口；现行运动 Mask、PCIe 与缓存语义见[接口入口](../../项目规划/接口与验收契约.md)，尚需负责人评审。此处端口不变，传输接口分别管理。

## 时钟、参数与握手

所有端口均相对 `clk` 上升沿采样。`rst_n` 低有效异步置位复位状态；板级逻辑须保证复位释放相对 `clk` 同步。复位会清除配置、待提交状态、错误状态和在途像素，但不清空行 RAM；帧首补边逻辑保证旧帧内容不会用于新帧有效输出。

参数默认 `MAX_WIDTH=2048`、`MAX_HEIGHT=2048`、`DEFAULT_WIDTH=640`、`DEFAULT_HEIGHT=480`。配置尺寸须在 1 到相应最大值之间；更改实例参数时须满足默认尺寸在范围内，且最大尺寸不超过 16 位表示范围。行 RAM 深度由 `MAX_WIDTH` 决定。

每个数据通道仅在 `valid && ready` 时传输一拍。生产者一旦拉高 `valid`，必须保持 `valid`、数据及元数据，直到该拍被接收。不得用脉冲 `valid` 代替握手，也不得在输出反压时继续覆盖输入。

两路处理互相独立，但每一路的整帧输出和 ROI 输出共享反压：任一有效输出未被接收，都可能令该路上游暂停。分流模块分别记录两个输出的待接收状态，不会在其中一支停顿时向另一支重复送像素。未使用的 ROI 输出应将 `roi_ready` 置 1；若只用 ROI，也必须接收或主动丢弃整帧输出，将 `full_ready` 置 1。

滤波器采用三组 8 位行 RAM，默认两路共 98,304 bit 逻辑行存储。正常行内可每周期接收 1 个像素，行末和帧末需要额外补边周期，且下游可产生任意反压。因此不能按“时钟频率等于持续有效像素速率”计算系统带宽。上下游 FIFO 与 DDR 带宽需待真实接口确定后评估。

去噪关闭时仍通过相同的行缓存与补边时序，整帧两通道保持对齐；旁路不是零延迟直通。首次输出需要等到相邻行数据可用，帧尾输出则会晚于最后一个输入像素。系统必须以握手和输出 EOF 判断完成，不能用固定延时猜测。

## 双路端口切片

`afh03_stereo_preproc` 的所有双路数组均将 lane 0 放在低位。`s_valid[i]`、`s_ready[i]` 及各输出的 `valid/ready[i]` 对应同一路。

- 输入像素：`s_data[8*i +: 8]`；输入元数据：`s_user[98*i +: 98]`。
- 整帧输出：`full_data[16*i +: 16]`；元数据：`full_user[147*i +: 147]`。
- ROI 输出：`roi_data[8*i +: 8]`；元数据：`roi_user[147*i +: 147]`。
- `cfg_pending[i]`、`cfg_error[i]`、`stream_fault[i]`：该路配置与流状态。
- `cfg_camera`：选择本次写配置的路号。两路分别保存自己的配置，不要求相同分辨率、帧率或帧开始时间。

## 输入 GRAY8

`s_data` 单路每拍为一个 8 位灰度像素，范围 0～255，按从左到右、从上到下逐行输入，不包含消隐区。可以输入直接灰度、单色传感器或已转换的亮度通道；Bayer 数据必须先完成适配。

单路 `s_user[97:0]` 位域如下：

- `[0]`：SOF，仅帧内首像素为 1。
- `[1]`：EOL，每行最后一个有效像素为 1。宽度为 1 时每个像素均为 EOL。
- `[33:2]`：32 位 `frame_id`。
- `[97:34]`：64 位 `timestamp_ticks`。

`frame_id` 与时间戳只在成功接收 SOF 像素时采样，其余像素上的这些字段被忽略。没有输入 EOF，内核按生效配置的宽、高识别帧尾。

坐标原点是输入有效图像左上角，x 向右、y 向下，均从 0 开始；当前实现不做几何校正或缩放。适配层应为每路递增帧号，并在采集侧选定明确的时间戳事件。时间戳单位、时钟来源和两路时间基准须在板级适配时约定。内核只透传数值，不能把“进入本模块的时刻”自动等同于曝光时刻；也不会伪造已完成同步校准。

## 输出格式

整帧 `full_data[15:0]` 的低 8 位是输入灰度，高 8 位是处理后灰度。这里的“原始”指本模块接收的 GRAY8，并非传感器 RAW/Bayer 或完整彩色数据。输出数量严格为生效宽度乘高度。

`roi_data[7:0]` 是配置指定的原始或处理后灰度。ROI 为半开区间 `[x, x+w) × [y, y+h)`，与图像范围取交集。宽或高为 0、ROI 起点完全在图外、或 ROI 关闭时，该帧不产生 ROI 像素。下游应结合配置和整帧 EOF 确定这一情况，不能无限等待不存在的 ROI EOF。

整帧和 ROI 共用单路 147 位元数据布局：

- `[0]`：输出首像素 SOF。
- `[1]`：输出行末 EOL。
- `[2]`：输出帧末 EOF；整帧指最后一行最后一像素，ROI 指裁剪结果最后一行最后一像素。
- `[18:3]`：16 位原图 x 坐标。
- `[34:19]`：16 位原图 y 坐标。
- `[66:35]`：32 位帧号。
- `[130:67]`：64 位采集时间戳。
- `[146:131]`：16 位 `config_tag`。

ROI 的坐标始终保留原图绝对坐标；ROI 的 SOF/EOL/EOF 则标记裁剪后输出边界。不要把 ROI SOF 误认为 x=y=0。宽高都是 1 的输出，其 SOF、EOL、EOF 可以在同一拍同时为 1。

## 配置写接口

`cfg_valid`、`cfg_ready`、`cfg_camera`、`cfg_addr[5:0]`、`cfg_wdata[31:0]` 构成写事务。仅在 `cfg_valid && cfg_ready` 时接收，地址以字节计，所有寄存器只支持整字写。桥接到实际 AXI/APB/PCIe 时，由桥接层处理地址译码、字节使能与读回；本接口没有读通道。

- `0x00`：`[15:0]` 图像宽，`[31:16]` 图像高。
- `0x04`：`[15:0]` ROI 起点 x，`[31:16]` 起点 y。
- `0x08`：`[15:0]` ROI 宽，`[31:16]` ROI 高。
- `0x0C`：bit 0 打开 3×3 去噪；bit 1 打开 ROI；bit 2 选择 ROI 来自处理后灰度（0 则选输入灰度）；其余位忽略。
- `0x10`：`[7:0]` 无符号亮度增益 Q6，64 表示 1 倍；`[24:16]` 为 9 位二进制补码偏置，范围 −256～255。其余位忽略。
- `0x14`：`[15:0]` 配置标签；其余位忽略。标签由软件维护，建议每次提交递增，配合帧号识别生效配置。
- `0x18`：提交，任意数据均触发快照。尺寸非法时拒绝提交并产生错误脉冲。

复位默认：图像 640×480（或实例参数指定值），ROI 起点 0、范围等于默认图像，去噪和 ROI 均关闭，增益 64，偏置 0，配置标签 0。

写 `0x00`～`0x14` 只修改影子配置。写 `0x18` 时复制一份完整快照到待生效配置，并拉高 `cfg_pending`；下一次成功接收合法帧首 SOF 后，快照整组生效且 `cfg_pending` 清零。正在处理的帧及尚未输出的帧尾继续使用各自随像素携带的旧配置。

已有待生效快照时，仍可修改影子寄存器，但这些修改不会改变快照。此时再次访问提交地址的 `cfg_ready=0`，生产者须等待，不能用新提交覆盖旧快照。若系统准备停采且已有 pending，应先让对应帧首被接收，或通过系统复位清理。

若首次提交和合法帧首恰好在同一上升沿发生，当前帧使用此前的活动配置，这次提交留待再下一帧。若已有 pending，则它在该帧首生效，而新的提交须待 ready 恢复后才能被接受。

未知地址或提交非法尺寸会产生该路一个周期的 `cfg_error`；活动配置不变。`cfg_error` 不是粘滞状态，CPU 总线桥应自行锁存或计数，避免轮询漏掉。

建议软件顺序：确认采集尺寸 → 写尺寸、ROI、处理参数、标签 → 提交 → 观察对应输出的 `config_tag`。运行中调整尺寸时，摄像头适配层必须在同一目标帧切换，不能只改内核尺寸。

## 像素处理与异常语义

去噪使用中心对齐的 3×3 加权窗口，四边复制最近像素，不缩小图像；后接 Q6 增益及有符号偏置，四舍五入后限制到 0～255。它不是模型的 mean/std 归一化、量化或自动曝光控制，默认旁路可以保持输入灰度数值。

输入 SOF 缺失、帧中重复 SOF、EOL 提前或缺失，都会置位该路粘滞 `stream_fault`。错误那一拍不会进入滤波器，此后该路 `s_ready=0`，直至复位。此前已进入流水线的数据可能继续产生部分输出，因此缓存适配层一旦看到 `stream_fault`，必须作废当前未提交帧，不能只相信已到达的像素。另一条 lane 继续运行；当前顶层共用复位，恢复故障时会同时清空两路在途帧。

长时间没有输入并不自动判作故障，因为合法反压和摄像头停采也可能造成空闲；帧超时、FIFO 溢出、PCIe 断链等由外层适配器监控并统一恢复。不要在 `stream_fault` 后只重新发送一个 SOF 试图恢复。

## 接入后的验收入口

先用已知测试图验证原始通道完全相等、整帧像素数与元数据正确；再启用去噪和 ROI，对照现有 Python 参考。之后分别验证采集域跨时钟、FIFO 满/溢出处理、DDR 写入和帧提交、PCIe 传输、CPU 帧号/配置标签追踪。最后再将软件时间校准、双路配对和 NPU 处理接到完整链路。每一阶段都应保留真实日志，不用综合结果代替上板验证。
