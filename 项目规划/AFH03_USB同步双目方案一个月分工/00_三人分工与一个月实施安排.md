# AFH03 USB 同步双目方案 三人分工与实施安排

## 第一部分 我们要做什么，各自需要哪些工具

我们要做的是一套乒乓球发球测量程序：从左右画面中找到球，记录球在空间中的运动，结合手和球拍的位置，给出离手、最高点、触拍附近的画面与抛球高度。当前先用电脑上的图片和视频文件完成开发，把输入、测量、识别和结果保存接成一条完整流程；相机和板卡到货后，再接入真实设备。

A 负责程序底座和整合。他准备大家共用的左右图像，管理每张图的编号、时刻和缓存，先用电脑完成准备交给 FPGA 的图像处理，再把 B 的测量和 C 的识别接起来。他使用 C++、CMake 和 OpenCV 开发主程序，使用 Python 整理样例；同时使用 Verilog、Icarus Verilog 和 TD 编写、仿真和准备 FPGA 前半部分的工程。设备到货后，A 负责相机输入、板内通信和设备适配。

B 负责测量和发球分析。他从 A 提供的图像里找球心，用左右视角计算空间位置，再整理轨迹和关键动作记录；同时负责 FPGA 后半部分的图像处理和输出整理。他使用 C++ 和 OpenCV 编写测量程序，使用 Python 生成已知位置的场景和绘制结果，使用 Verilog、Icarus Verilog 和 TD 完成 FPGA 部分。相机到货后，B 负责重新测定真实相机参数和记录实物测量结果。

C 负责数据、识别模型和独立复核。他整理允许使用的图片与视频，补齐球、手和球拍标签，训练能在电脑上实际运行的模型，并准备大家共同使用的测试材料。他使用 Python、PyTorch 和图像标注软件处理数据与训练，使用 C++ 整理识别输出，使用 PC Linux 和 Rockchip 的模型转换工具准备板端文件。真实相机到货后，C 负责补充灰度样本、更新模型并记录板端运行结果。

三人都可以在 Windows 或 Linux 电脑上开展开发，共用程序还需要在 PC Linux 中构建和运行。A 提供输入和整合入口，B 提供测量结果，C 提供识别结果和独立复核记录；三人共同补标、复现同一输入并定位问题。电脑上的实现、仿真和真实设备运行分别保留记录，便于接入硬件时逐层对照。

## 第二部分 具体实现方法与交付安排

### 总体数据流与共用入口

正式目标沿用 AFH03 的 RK3576J 与 PH1A90SEG324，配合 72°、3.6 mm 双 OV9281 USB3 模组，拼接 YUY2 为 2560×720@60 fps，每眼 1280×720，安装基线 150～200 mm。RK 保存原始灰度图和 8 对原图缓存，每眼生成 640×360 搜索图，经 PCIe 交给 FPGA；FPGA 返回 1 bit Mask，CPU 在同帧原图的 256×256 ROI 内求球心、三维和事件，NPU 异步提供 ball、hand、racket 类别框。

当前由 A 使用 C++17、CMake 和 OpenCV 建立文件回放入口。FrameSource 提供图像，MotionBackend 提供运动前端，DetectorBackend 提供类别检测；FileFrameSource 读取拼接 YUY2 或成对 GRAY8，输入清单记录尺寸、stride、pair_id、左右关系和采样时间。按 Y0 U Y1 V 提取原 Y 值并拆分左右眼，设备适配层以后分别接 UVC/V4L2、PCIe FPGA 和 RKNN Runtime，同时准备 AArch64 工具链及厂商库清单。

### A 的整数参考、前三级 RTL 与系统整合

A 实现七级 C++ 整数参考：Gaussian、同眼帧差、阈值、腐蚀、膨胀、膨胀、腐蚀。2×2 缩图的当前取整为四像素和加 2 后右移 2 位；Gaussian 使用 3×3 的 [1,2,1] 外积核，取整为加权和加 8 后右移 4 位；绝对帧差大于 12 为前景，各级使用 replicate 边界。这些参数沿用现有草案，由 A/B 评审后记录版本。

A 负责 Gaussian、帧差和阈值三段 RTL，B 接后四级与打包。左右眼独立保存前帧和 reference_id，仅在完整成功处理一帧后更新对应眼参考；首帧输出零 Mask 并标记 reference_valid=false。使用行缓存、valid/ready 流控、模拟 DDR 和 DMA 联调，加入边缘、复位、短帧、随机停顿及左右切换。正式板卡另接 DDR3L 与 PCIe 工程；H10 CK203 DDR3 作为可选预验证平台。

A 管理有限队列和原图引用，按 u=2u_s+0.5、v=2v_s+0.5 将搜索中心恢复到原图，裁图时保留 ROI 原点、有效范围及补齐信息。异步检测保留必要裁块或有限原图引用，迟到类别框按 source_pair_id 归档。整合 B/C 模块后导出 CSV/JSON，保存原图、Mask、ROI、球心、类别框、轨迹和事件证据，并提供逐帧叠加回放与共用显示结果。

### B 的后四级 RTL、球心、三维与事件

B 实现腐蚀→膨胀→膨胀→腐蚀四级 RTL，使用 3×3 邻域和 replicate 边界，独立复核 A 的整数参考与中间图。640×360 Mask 按 1 bit 打包，每眼每行 80 字节、每对共 57,600 字节；位序和描述符布局由 A/B 评审。CPU 使用 8 邻域连通域筛选候选，在同帧原图 256×256 ROI 内测量；局部 64×64 区域使用 Otsu，检查极性，结合闭运算与 moments 求亚像素球心，Sobel 用于局部轮廓与部分遮挡分析。

标定依次使用 OpenCV 的 findChessboardCornersSB、calibrateCamera、stereoCalibrate 和 stereoRectify，世界坐标通过 solvePnP 建立。运行时只对球心使用 undistortPoints，结合 R1/R2、P1/P2，再用 triangulatePoints 求三维点；齐次归一化得到 Xrect，按 Xc=R1ᵀXrect、Xw=Rcwᵀ(Xc−tcw) 恢复世界坐标，Rcw、tcw 表示世界到左相机的变换。沿用 X 为台宽、Y 为台长、Z 向上和米制单位，保存几何质量及无效原因。公开棋盘和独立双目合成用于程序练习，最终标定使用锁焦后的真实相机。

B 使用实际 dt 和自由飞行重力建立三维 Kalman 跟踪，将预测位置反投影为 ROI，在顶点附近 Mask 为零时继续局部测量。持球准备、上抛、顶点、下落和触拍组成状态序列，结合来源帧的 hand、racket 框及球的实际观测给出事件区间。使用有效实际观测进行带权稳健最小二乘拟合，水平采用线性模型、竖直采用二次模型，求最高点和抛球高度；观测、滤波、预测分栏，取消动作或证据不足时记录相应状态。

### C 的数据、模型与板端准备

C 按人员或场次划分训练、验证和独立测试集，复核 ball、hand、racket 三类标签，与 B 准备合成双目和事件场景。模型输入沿用原始灰度复制为 3 通道，等比例缩放并以 114 补边到 640×640；保存 ROI 原点、缩放比例和补边量，框逆变换回原图。归一化沿用 mean=0、std=255，合计执行一次。

采用 Rockchip 适配的 YOLOv8n，固定代码提交、初始权重、类别顺序和配置，使用 PyTorch 训练及运行 PC 模型，按适配方式导出 ONNX。C++ 后处理按实际三类输出实现 DFL 解码与 NMS，并衔接 Rockchip Model Zoo。使用 RKNN Toolkit2 在支持的 PC Linux 环境中针对 rk3576 转换浮点与 INT8 模型，校准使用训练侧代表图；保存转换日志、校准清单、RKNN Runtime 与驱动版本。相机到货后补真实灰度样本并更新训练和校准，AFH03 到货后记录实际 NPU 推理。

C 向 A 提供 DetectorBackend 调用材料，向 B 提供带 source_pair_id、眼别、采样时间、ROI 与模型版本的类别框。检测调用总预算沿用每秒 20～30 次，左眼优先，必要的右眼调用共享预算。实际 PC 模型和标记为 replay 的检测框回放分别记录结果；独立真值只供评分，C 负责整理检测、球心、三维和事件的复核报告及失败样例。

### 三人的共同约定

输入帧、运动结果、球心和类别框都保留来源编号、采样时间、眼别及配置版本。原图与 ROI 保持同帧对应，预测和迟到框保留来源；三人共用固定输入定位差异。接口布局、模型输入、量化参数、坐标系与判罚阈值沿用当前草案，相关变更先说明兼容影响并由模块负责人评审。代码、配置、工具版本、运行日志和文件校验信息随交付记录，模型权重和原始视频用本地清单引用。
