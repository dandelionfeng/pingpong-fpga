# A 个人分工说明：输入、通信与系统整合

## 第一部分 你要做什么，需要哪些工具

你负责把整个项目的程序接起来，让大家在没有相机和板卡时，也能用电脑中的图像文件完成开发。你要让程序读入左右图像，保留原始画面，准备供后续处理的小图，并管理每张图的编号和拍摄时刻。其他两人拿到你提供的输入后，就能分别开发测量和识别功能。

你还要先用电脑程序完成原本准备交给 FPGA 的图像处理，为硬件实现提供对照；同时编写 FPGA 前半部分的逻辑，并在电脑上仿真。你负责把 B 的测量程序和 C 的识别程序接入同一个运行入口，让系统能够从图像一直运行到轨迹和发球结果，并保存过程中的画面与记录。

主程序使用 C++，这样电脑上完成的代码可以继续用于后面的板端程序。CMake 用来管理编译，OpenCV 用来读图、裁图和显示结果。Windows 可以用于日常开发，Linux 用来检查同一套程序的运行，并准备后续板端环境；当前使用电脑上的 Linux 即可。Python 用来生成样例、整理文件和辅助检查。

FPGA 部分使用 Verilog 编写逻辑，使用 Icarus Verilog 在电脑上运行仿真，使用 TD 准备正式 FPGA 芯片的工程和综合。拿到设备后，再使用厂商提供的软件包、驱动和示例工程，把文件输入换成相机输入，把电脑上的图像处理换成 FPGA 处理。你向 B 提供原图、小图和运动区域结果，向 C 提供图像及调用入口，并负责记录三人程序组合后的运行情况。

## 第二部分 具体实现方法与交付材料

### 共用程序与文件输入

以 C++17、CMake 和 OpenCV 建立无界面的回放程序，核心代码分别在 Windows 和 PC Linux 构建。正式目标沿用 AFH03 的 RK3576J 与 PH1A90SEG324。FrameSource 负责提供图像，MotionBackend 负责运动前端，DetectorBackend 负责类别检测；各模块共用帧编号、采样时间、配置版本和错误状态，设备相关代码放在对应适配层。

FileFrameSource 支持拼接 YUY2 文件和成对 GRAY8 文件，输入清单记录尺寸、stride、左右关系、pair_id 和时间来源。按 Y0 U Y1 V 顺序逐行提取原始 Y 值，保持亮度范围；将 2560×720 图像拆成两张 1280×720 灰度图。行填充、文件截断、缺失单眼、重复帧和时间跳变都要有明确处理及日志。

### 原图、搜索图与缓存

原图环形缓存保留 8 对左右图像。每眼进行 2×2 平均，生成 640×360 搜索图；当前取整起点为四像素和加 2 后右移 2 位。搜索图球心映射回原图时使用 u=2u_s+0.5、v=2v_s+0.5，框边界按原图覆盖范围换算。局部测量从同一 pair_id 的原图裁出 256×256 ROI，保存裁切原点、有效范围和补齐信息。

从入队到局部裁图、显示结束，图像引用需要保持有效。异步检测额外保留必要裁块或有容量上限的原图引用，避免 8 对环形缓存覆盖仍在使用的画面。检测任务、完成任务和显示任务采用有限队列，持续慢处理时记录替换、超时和过期状态。

### 整数参考与前三级 FPGA 逻辑

完成七级 C++ 整数参考：Gaussian、同眼帧差、阈值、腐蚀、膨胀、膨胀、腐蚀。Gaussian 使用 3×3 的 [1,2,1] 外积核，当前取整为加权和加 8 后右移 4 位；帧差取绝对值，初始阈值采用差值大于 12 为前景。各级采用 replicate 边界，并保存中间图，供 B 独立复核和 RTL 对照。上述取整、边界和阈值沿用现有配置草案，由 A/B 评审后记录版本。

你实现 Gaussian、帧差和阈值三段 RTL，B 实现后续四段形态学和掩膜打包。前三级使用行缓存和 valid/ready 流控，testbench 加入随机停顿、左右切换、边缘输入及复位。先通过仿真存储模型验证读写和处理逻辑，再准备 PH1A90SEG324 的工程；综合、仿真和实物运行分别记录工具、配置与实际结果。

### 前帧状态与通信模拟

左右眼各自保存前帧与 reference_id，仅在完整成功处理一帧后更新对应眼的参考。首帧输出零 Mask 并标记 reference_valid=false；短帧、失败帧和配置切换按共同约定处理。用模拟 DDR 和 DMA 完成提交、完成通知、背压、超时及复位的联调，检查帧编号、眼别和配置版本是否一致。描述符布局与位序继续按接口草案评审。

### 三人模块整合与结果保存

将 CPU MotionBackend、B 的球心及三维事件模块、C 的实际 PC 模型接入同一程序，并保留单独的检测框回放模式。向队列注入延迟、乱序和持续慢处理，所有类别框携带 source_pair_id；迟到结果归档到来源帧，过期结果记录状态。每帧测量与异步检测分别调度，检测调用总预算与 C 共同管理。

无界面入口导出 CSV/JSON，保存原图、Mask、ROI、球心、类别框、轨迹和事件证据。叠加回放与 GUI 使用同一份测量结果，并标出 CPU 文件回放、检测框回放或 PC 实际模型等运行模式。异常时保留输入与中间结果，便于三人定位出错的模块。

### 设备适配与部署准备

准备 PC Linux 构建说明、AArch64 工具链和厂商库清单，登记缺少的 SDK、驱动与 IP。相机到货后，通过 UVC/V4L2 替换 FrameSource，核实实际格式、stride、曝光和帧时间；AFH03 到货后，验证 DDR3L、PCIe 和固定图 DMA，再替换 MotionBackend。局部测量和事件处理继续使用共用核心，CPU 与 FPGA 比较使用相同输入和算法配置。

### 需要交付的材料

交付共用 C++ 程序、构建与运行说明、配置文件、输入清单、固定样例、缓存与接口说明，以及整合 B/C 模块的运行入口。附上回放导出的图像、CSV/JSON、异常日志、配置版本和文件校验信息。

交付前三级 RTL、testbench、仿真输入、中间图、对照日志和波形；附上已有的目标工程与综合记录，以及工具和 IP 清单。交付设备适配代码、部署说明、依赖版本及待补材料清单，已完成的设备检查附相应原始记录。

你是本项目负责输入、通信与系统整合的 agent，请在项目仓库中定位当前总分工和 A 的个人分工，以个人分工第二部分为依据完成 A 的工作。先按 AGENTS.md 阅读当前方案、接口契约和最新交接，检查已有代码、工具环境及输入样例，整理输入输出、现有成果、待办和依赖，再自主拆成可独立实现与联调的任务。使用 C++17、CMake、OpenCV 完成 FileFrameSource、缓存、七级整数参考和共用运行入口，使用 Verilog、Icarus Verilog、TD 完成前三级 RTL 及相应记录，并通过 FrameSource、MotionBackend、DetectorBackend 接入 B/C 的模块；同帧 ROI、前帧状态、有限队列与来源帧号按正文约定处理。持续推进代码、联调和实际复现；缺少硬件或厂商 SDK 时，先完成文件输入、模拟通信和部署准备，登记真实阻塞，继续完成可独立执行的部分。只修改本角色职责内的文件，在任务分支上保留他人改动；涉及接口等共用约定变更时先说明兼容影响并提交负责人评审。交付代码、运行入口、实际命令与日志、真实结果、未完成项和下一步，并按现有交接模板记录，分别标明 PC 运行、RTL 仿真、综合与实机结果。
