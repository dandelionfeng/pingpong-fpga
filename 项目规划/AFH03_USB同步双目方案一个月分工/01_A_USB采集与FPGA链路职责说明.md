# A USB 采集与 FPGA 链路职责说明

你负责把同一次曝光的左右图像稳定送进处理链，并让 FPGA 的候选准确回到原始双目帧。准备周期为 2026-09-29 至 2026-10-28；当前路线按自主命题设计。[R1]

## 你的工作怎么串起来

先核对 AFH03 上 RK3576J Type-C USB3 主机的实际接口、主机模式、供电与线缆，接入已同步双目模组。两只普通 USB Host 接口在板卡手册中列为 USB 2.0；高带宽视频接入点按 Type-C SuperSpeed 路径设计。[R2] 用 `lsusb -t` 核对 5000M 链路，以 `v4l2-ctl --list-formats-ext` 或厂商 ARM64 SDK 查左右各 1080p 60 fps 的真实格式。记录完整帧、丢帧、配对序号与曝光设置。摄像头型号未定时，先用成对图像文件建立相同软件接口。

每对图像分配 `pair_id`，分别保存左、右原图和摄像头帧序号、设备时间戳、主机接收时间、像素格式、行步幅及配置版本。原图放 RK 环形缓存，保持到 FPGA 候选返回、ROI 裁切与证据保存完成。双目 GRAY8 1080p60 的纯像素流量约 248.83 MB/s；8 对紧凑帧约 33.18 MB。实际缓存按格式和步幅重新核算。[R1]

从同一对原图生成左右各 960×540 GRAY8 搜索图，通过 PCIe H2C 送 FPGA；接收 B 的双路候选后，从同一 `pair_id` 取左右 256×256 ROI，按 B 的标定映射形成配对局部图，再送 FPGA 做球心细化。搜索图加每帧一对 ROI 的纯载荷约 70.07 MB/s。B 的候选与球心经 C2H 返回，A 负责超时、排队、缓冲释放、配置生效帧与丢帧记录。PCIe 2.0×1 每方向约 500 MB/s 是编码后理论上限，DMA 吞吐由板上计数确定。[R3]

FPGA 侧你负责 PCIe 输入输出、数据包解帧、DDR 前帧访问、队列、时钟复位和 B 的 RTL 顶层集成。B 负责滤波、帧差、形态学、候选及球心算法。先用递增棋盘格、角点亮斑、错序帧及暂停消费者测试；每次回包都带 `pair_id`，使 C 的模型和 B 的三维结果可回查原图。

## 每周交付

- 第 1 周：Type-C SuperSpeed 与 PCIe 并发配置证据、成对文件模拟采集、H2C/C2H 合成帧回环；与 B/C 评审像素格式、坐标和缓冲寿命。
- 第 2 周：真实双目采集、左右完整帧率与配对日志、搜索图进入 FPGA 并返回候选；静态球原图回查。
- 第 3 周：同帧双 ROI 往返、回放界面和事件原图保存；持续队列与错误恢复。
- 第 4 周：连续运行、USB/PCIe 吞吐与 CPU 占用；同一批帧上对照 FPGA 和 RK 软件搜索，整理 P50/P95 延迟及演示脚本。

采集与基础框标注由三人分担；你额外负责参考录像、板端日志和展示界面。第 1 周交给 B/C 的最小包是左右原图、搜索图、`pair_id`、格式、步幅、缩放规则及一份可回放脚本。交接按 `handoffs/TEMPLATE.md` 附真实命令与输出。

## 调试时按什么顺序查

先确认物理速率，再确认图像格式。`lsusb -t` 中的 5000M 说明主机与相机建立了 SuperSpeed 链路；`v4l2-ctl --list-formats-ext` 说明当前驱动公开了哪些左右模式。接着抓取固定时长的原始帧，统计左右完整帧数、序号跳变、主机队列峰值和每帧实际步幅。带时间戳的日志与原始帧一起保存，便于 B 判断同步、C 重放模型输入。

PCIe 调试从合成图案开始：左图递增数字、右图不同常量，验证左右标识；再把亮点放在四角与边缘，验证 1080p 到 960×540、到 256×256 ROI、再到 FPGA 球心的坐标映射。最后切换真实球视频，记录每级输入输出 `pair_id`。队列拥塞时先保留原图和状态计数，再根据处理预算调整显示和调试存盘频率。

交付给评委看的记录应包含一张清楚的数据流图、一段连续运行日志、同图 FPGA/软件候选对照及可回放的异常样例。这样接口和硬件加速的作用都有具体证据。
