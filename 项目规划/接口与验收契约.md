日期：2026-09-19。状态：设计规范，根据 MLK-H10-CK203-PH1A180 与外接 RK3566 边缘 NPU 异构架构升级。负责人：A 总体与采集、B 预处理与千兆网传输、C 模型与几何测量。

> [!NOTE]
> **Agent 协作变更说明（2026-09-19 v0.4）**：
> 1. **异构节点与物理通信定型**：系统由前端安路 **MLK-H10-CK203-PH1A180** 与外接 **RK3566 边缘计算板**构成，二者通过**板载千兆以太网（Gigabit Ethernet / UDP）**互联。
> 2. **数据流轻量化契约**：明确 FPGA 在片上提取双目 128×128 运动局部 ROI 并打包推流（总吞吐仅约 4.2 MB/s，利用率 3.8%），避免全图 245.8 MB/s 导致网络拥塞。
> 3. **UDP 传输帧头与对齐规范**：制定标准 UDP 应用层数据包结构，包含全局 `pair_id`、微秒硬件时间戳 `timestamp_ticks`、原图绝对偏移坐标 `(roi_x0, roi_y0)` 与 CRC 校验。
> 4. **RK3566 NPU (1.0 TOPS) 模型与输出 Schema**：制定专用轻量小目标网络在 RKNN-Toolkit2 下的输入输出维度与置信度阈值。

## 1. 坐标、时间与数据真实性

1. **原始像素坐标系**：
   - 原点位于双目传感器（1280×800）有效图像左上角，水平向右为 $u$ 轴，垂直向下为 $v$ 轴；单位为像素（px），球心定位允许小数（亚像素）。
2. **世界物理坐标系（右手系）**：
   - 原点定义于球台近端发球区基准标记处；
   - $X$ 轴沿球台宽度水平向右，$Y$ 轴沿球台长度水平向前，$Z$ 轴严格沿铅垂方向竖直向上；
   - 系统内部存储与计算统一采用米（m），HDMI 界面展示采用厘米（cm），禁止混淆。
3. **帧标识与曝光同一性**：
   - `frame_id` 为单目从启动起递增的独立帧序号；
   - `pair_id` 为由 FPGA FSIN 触发脉冲发生器生成的**全局双目曝光对编号**，只有被同一 FSIN 脉冲触发曝光并成功接收的左右帧才具有相同 `pair_id`；
   - `t_fsin_trigger_ticks` 表示硬件触发脉冲发生的 FPGA 内部计数器计数值（时钟基准 100MHz，1 tick = 10ns）；
   - 因采用**全局快门（Global Shutter）**，全画幅所有像素同时受光，左右目物理时间偏差严格保证在 10μs 以内。
4. **数据点状态标注**：
   - 每一个输出轨迹点必须严格标明 `observed`（双目有效观测点）、`predicted`（卡尔曼滤波单帧预测点）或 `invalid`（目标丢失或遮挡点）；
   - `predicted` 点仅用于平滑跟踪连续性，**严禁计入离手高度与最高点拟合的有效采样点中**！
5. **ROI 逆变换还原**：
   - 送入 RK3566 的 128×128 ROI 数据包中严格附带原图偏移量 $(roi\_x0, roi\_y0)$；
   - RK3566 NPU 输出的局部球心坐标 $(u_{local}, v_{local})$ 经亚像素质心细化后，首先逆映射回 1280×800 全图：
     $$u_{full} = u_{local} + roi\_x0, \quad v_{full} = v_{local} + roi\_y0$$
   - 还原为全图坐标后，方可带入双目外参矩阵进行去畸变与空间三角化。

## 2. FPGA-RK3566 千兆以太网 UDP 数据包协议

FPGA 内部 UDP 发送模块与 RK3566 接收端遵循如下统一数据包结构（小端序 Little-Endian，固定长度）：

| 字节偏移 | 字段名称 | 数据类型 | 字段含义与取值范围 |
|---|---|---|---|
| `0x00` | `magic_num` | `u32` | 固定同步魔数：`0x50494E47`（ASCII: "PING"） |
| `0x04` | `proto_version` | `u16` | 协议版本：`0x0004`（v0.4） |
| `0x06` | `header_bytes` | `u16` | 帧头长度：固定 64 字节 |
| `0x08` | `pair_id` | `u64` | 全局双目硬件同步触发编号（单调递增） |
| `0x10` | `frame_id` | `u64` | 单目帧流水序号 |
| `0x18` | `timestamp_ticks` | `u64` | FPGA 硬件 100MHz 计数器时间戳（10ns 精度） |
| `0x20` | `camera_id` | `u8` | 相机编号：`0x00` = 左目，`0x01` = 右目 |
| `0x21` | `pixel_format` | `u8` | 像素格式：`0x01` = GRAY8 / RAW8 单通道灰度 |
| `0x22` | `reserved0` | `u16` | 预留对齐 |
| `0x24` | `full_width` | `u16` | 传感器全幅宽度：固定 1280 |
| `0x26` | `full_height` | `u16` | 传感器全幅高度：固定 800 |
| `0x28` | `roi_x0` | `u16` | ROI 区域在原图中的左上角水平坐标 (0~1152) |
| `0x2A` | `roi_y0` | `u16` | ROI 区域在原图中的左上角垂直坐标 (0~672) |
| `0x2C` | `roi_width` | `u16` | ROI 宽度：固定 128 |
| `0x2E` | `roi_height` | `u16` | ROI 高度：固定 128 |
| `0x30` | `payload_bytes` | `u32` | 像素载荷字节数：固定 $128 \times 128 = 16384$ 字节 |
| `0x34` | `motion_energy` | `u32` | FPGA 硬件差分计算得到的局部运动能量指标 |
| `0x38` | `reserved1` | `u24` | 预留对齐 |
| `0x3C` | `header_crc` | `u32` | 前 60 字节的 CRC32 校验码 |
| `0x40` | `pixel_data` | `u8[16384]` | 128×128 逐行扫描灰度像素数据 |

数据包总大小：$64 + 16384 = 16448$ 字节（可通过 IP 分片或 Jumbo Frame 传输，典型为 2 个标准 UDP 数据包分片）。

## 3. RK3566 NPU (1.0 TOPS) 模型与推理契约

1. **模型输入规约**：
   - 尺寸：$1 \times 128 \times 128 \times 1$（单通道灰度）；
   - 数据格式：`INT8`，均值 0，方差 255（输入已由 FPGA 完成线性灰度归一化）；
   - 目标网络：Tiny-BallNet（单类目小球回归定位网络，参数量 < 50k）。
2. **NPU 输出规约**：
   - 置信度分数 $Score \in [0.0, 1.0]$，阈值设为 0.65；
   - 粗球心坐标 $(u_{box}, v_{box})$ 相对 128×128 局部窗口归一化；
   - 单次推理时间：RK3566 NPU 必须保证单张 128×128 输入耗时 $\le 2.5\text{ ms}$。
3. **亚像素质心细化（Cortex-A55 逻辑）**：
   - 在 NPU 预测的球心位置周围 $15 \times 15$ 窗口内执行灰度加权质心法：
     $$u_{sub} = \frac{\sum u \cdot I(u, v)}{\sum I(u, v)}, \quad v_{sub} = \frac{\sum v \cdot I(u, v)}{\sum I(u, v)}$$
   - 随后与包头中的 $(roi\_x0, roi\_y0)$ 相加，得到 1280×800 原图亚像素坐标。

## 4. 测量输出记录 Schema (v0.4)

RK3566 最终输出的比赛测量记录遵循如下 JSON 格式。无法计算的值统一填 `null`，禁止补零：

```json
{
  "schema_version": "0.4",
  "event_id": "shot-20260919-001",
  "hardware_system": "Anlogic_PH1A180_plus_RK3566_Heterogeneous",
  "camera_sensor": "OV9281_Stereo_GlobalShutter_120fps",
  "sync_method": "FPGA_FSIN_Hardware_Trigger",
  "interconnect": "Gigabit_Ethernet_UDP",
  "release_timestamp_ticks": 108492040,
  "apex_timestamp_ticks": 126582040,
  "flight_duration_ms": 180.9,
  "release_pos_m": [0.125, 0.450, 0.112],
  "apex_pos_m": [0.138, 0.462, 0.288],
  "height_m": 0.176,
  "height_uncertainty_mm": 6.8,
  "angle_chord_deg": 4.52,
  "angle_velocity_deg": 2.31,
  "valid_stereo_frames": 22,
  "predicted_frames": 1,
  "decision_status": "satisfied",
  "reason_codes": []
}
```

### 4.1 异常原因编码（reason_codes）

- `stereo_unsynced`：双目 FSIN 触发或网络丢包导致立体失步；
- `release_occluded`：离手瞬间受球拍或身体遮挡无法确定离手位置；
- `apex_not_observed`：小球飞出视野或最高点未被完整采集；
- `out_of_calibration_volume`：小球运动轨迹超出有效标定几何空间；
- `insufficient_observations`：上升阶段有效双目观测点少于 12 帧；
- `fit_residual_high`：二次抛物线拟合残差过大；
- `near_threshold`：高度处于 0.14m ~ 0.16m 临界模糊区间，转入人工复核。

## 6. 合入前一致性检查清单

1. **左右相机同一性**：确认左右目均为 OV9281 全局快门，FSIN 硬件脉冲同频同相驱动；
2. **网口协议版本一致**：确认 FPGA UDP 发送端与 RK3566 接收端协议版本均为 `0x0004`；
3. **坐标逆变换对齐**：确认局部球心加上 $(roi\_x0, roi\_y0)$ 后还原至 1280×800 全图坐标无偏移；
4. **标定参数匹配**：双目内外参标定矩阵与当前固定相机机械间距严格对应；
5. **高度与角度定义一致**：确认计算公式为 $h = Z_{\text{apex}} - Z_{\text{release}}$，同时输出连线角 $\theta_c$ 与初速度角 $\theta_v$。
