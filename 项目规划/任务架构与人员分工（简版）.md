# 任务架构与人员分工（简版）

2026-09-20｜基于实施规划 v1.3｜内部交付：11 月 3 日，比赛提交：11 月 4 日。

## 1. 我们要做什么

用双目相机观察乒乓球发球，计算抛球高度和角度，在屏幕显示轨迹、测量结果和“满足条件 / 疑似违例 / 待复核”。

## 2. 系统架构

```text
双目 OV9281 相机
        ↓
安路 PH1A180 FPGA
  A：同步触发 → 图像采集 → DDR 缓存
  B：图像预处理 → 裁剪小球区域（ROI）→ UDP 发送
        ↓ 千兆网
RK3566 计算板
  C：接收图像 → 小球检测 → 三维轨迹 → 高度/角度 → 显示结果
```

电脑用于训练模型、标定和开发，最终演示由两块板卡完成。

## 3. 三人分工

| 人员 | 主要任务 | 交付给谁、交付什么 |
|---|---|---|
| **A：蒲公英（微电子）** | 板卡与相机配置、双目同步、图像采集、DDR 缓存、FPGA 顶层集成 | 给 B 稳定的左右图像及帧编号；负责整机硬件可启动 |
| **B：微电子同学** | 运动区域提取、ROI 裁剪、UDP 打包发送、传输异常统计 | 给 C 成对 ROI、原图位置、帧编号和时间信息；与 C 联调网络 |
| **C：人工智能同学** | 接收程序、小球检测与 RKNN 部署、双目标定、三维计算、发球判断、结果界面 | 交付 RK3566 上可运行的测量与显示程序 |

**三人共同完成**：采集与标注数据、整机测试、技术报告、演示视频。A 统筹进度；C 的任务最多，数据整理和材料制作不要都压给 C。

## 4. 只盯住五个节点

| 时间 | 必须看到的结果 |
|---|---|
| **9/20—9/25** | 核对硬件与例程；A/B 确认图像接口，B/C 确认数据包格式；C 跑通离线检测 |
| **9/26—10/9** | 双目图像进入 FPGA，裁剪后通过网口到达 RK3566，能够检测小球 |
| **10/10—10/16** | 完成标定，串起三维轨迹、高度/角度计算和基础显示 |
| **10/17—10/23** | 用真实发球测试误差、漏检和稳定性；修复问题，冻结主要功能 |
| **10/24—11/3** | 整理源码、模型、测试报告和视频；彩排并提交，11/4 仅核对回执 |

这些是计划节点，实际帧率、精度和延迟以上板测试为准。硬件未到时先做仿真与离线算法，不能代替硬件验收。

## 5. 简单协作规则

- **先打通整条链路，再提高性能。** 暂缓多机位、自动重标定、复杂界面等扩展。
- **先统一接口，再分头写代码。** 当前 UDP 分包和包头布局仍需 B/C 确认，详见 [待确认项](../docs/实施前待确认项.md)。
- **一个任务一个分支，队友看过再合并。** 每周一起演示一次当前能运行的功能。
- **AI 分工：** 普通 agent 做独立模块初稿、测试和文档；Codex 集中处理接口审查、跨模块联调和难题。上板、测量与结果确认由人负责。

本简版用于日常分工；具体协议、参数和验收方法仍查阅原实施规划与接口契约。
