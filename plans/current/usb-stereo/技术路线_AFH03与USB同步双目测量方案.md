# AFH03 与 USB 同步双目乒乓球发球测量方案

版本：2026-09-30 实施步骤细化版。申报定位：2026 FPGA 创新设计赛道**自主命题**。准备周期：2026-09-29 至 2026-10-28。

## 1 先说清楚这条路线

选用汇博视捷 HBVCAM-W2307-2 V11 系列的双 OV9281 USB3 模组，100°、2.1 mm 手动调焦版本。摄像头模组双目已同步、支持手动曝光；经 AFH03 的 RK3576J J4 高速 Type-C 口，以 **YUY2 格式输出 2560×720 左右拼接图，每秒 60 对，每眼 1280×720**。左右镜头用刚性支架固定，光心基线为 150～200 mm，初期机位距目标区域约 1.3～1.5 m，手动调焦后锁紧镜头。[R1、R2]

RK 保存左右灰度原图，将每眼 640×360 搜索图经板内 PCIe1 交给安路 PH1A90SEG324 FPGA。FPGA 先做运动搜索，指出球可能出现的位置；RK 从同一帧原图取左右各 256×256 局部图，再交 FPGA 测量球心。RK CPU 利用左右球心和标定参数求三维位置，NPU 运行 **YOLOv8n 三类检测模型**，提供身份、遮挡和事件提示。最终得到离手点、最高点、触拍点，以及抛球高度、方向和简洁的三维轨迹。

FPGA 承担每帧搜索和精细球心测量，输出的是三维重建直接使用的像素观测。CPU 负责采集协议、图像缓存、坐标换算和轨迹计算；NPU 提供语义识别。处理链路为“相机 → RK 灰度与缩图 → FPGA 搜索 → RK 同帧局部图 → FPGA 球心 → RK 三维与关键点”，AI 与这条链路并行。中间帧用于连续跟踪和轨迹拟合，展示重点放在三个关键点。

## 2 从相机到三个关键点的具体步骤

### 2.1 固定机位并完成双目标定

先安装相机，让两眼都能看到发球手、上抛空间和球拍。保持镜头位置、光心间距和焦点固定，采用稳定补光。曝光初始按约 0.5 ms 设置，曝光与增益采用手动控制；程序按相机控制项的实际单位填写参数。启动采集时固定 2560×720、60 fps、YUY2，后续训练与运行都使用这组分辨率。

使用内角点为 9×6 的棋盘格标定板，实测方格边长并以米输入。拍摄约 25～40 对同步图，覆盖中心、边缘、不同距离和倾斜角度。OpenCV `findChessboardCornersSB` 提取角点，分别用 `calibrateCamera` 求两眼内参和畸变，再用 `stereoCalibrate` 配合 `CALIB_FIX_INTRINSIC` 求相机间的旋转与平移；`stereoRectify` 生成校正旋转和左右投影矩阵。保存内参、畸变、相机相对位姿、投影矩阵与标定版本。[R3]

在球台上建立世界坐标：X 沿台面横向，Y 沿球台长度方向，Z 竖直向上，单位为米。取若干已知三维位置的棋盘格角点，使用 `solvePnP` 得到相机到世界坐标的变换。这样程序算出的“向上”对应真实竖直方向，抛球高度就是世界坐标中的高度变化。标定与世界坐标参数随相机配置一同保存。

### 2.2 在 RK 端采集并拆分左右灰度图

采集程序采用 Linux V4L2 的 C++ 接口。设置 `V4L2_PIX_FMT_YUYV`，即 Linux 中与 YUY2 对应的格式，申请 MMAP 缓冲区，按 `QBUF → STREAMON → DQBUF → 处理 → QBUF` 循环读取拼接帧。每个完整拼接帧分配一个 `pair_id`，同时保留驱动序号、帧时间、像素格式和行步幅；左右图沿用同一个 `pair_id`。[R4、R5]

YUY2 的两个相邻像素按 `Y0 U Y1 V` 排列。程序逐行按驱动返回的步幅读取，每个像素取其中的 Y 字节，保留实际 8 位亮度；拼接图横向第 0～1279 列作为左眼，第 1280～2559 列作为右眼，得到两张 1280×720 GRAY8 图。相机左右排列在配置中固定。提取出的 Y 值贯穿图像处理与训练预处理。[R4]

RK 以 8 对左右灰度图组成环形缓存，图像从入队到局部图裁切和显示结束保持引用。随后对每眼做 2×2 像素平均，得到 640×360 搜索图。搜索图像素中心映射到原图时采用 `u原=2u搜索+0.5`、`v原=2v搜索+0.5`；候选框边界另按覆盖范围映射。缩图先用 C++ 实现，后续可用 RK RGA 加速相同的取样规则。

### 2.3 通过 PCIe 组织两轮图像处理

RK 为主机，FPGA 为 PCIe 端点，使用板内 PCIe1 的双向 DMA。主机送入 FPGA 的方向称 H2C，FPGA 返回主机的方向称 C2H。每个图像任务带 `pair_id`、左右标识、任务类型、宽高、步幅和配置版本，像素区使用连续 GRAY8 数据；返回的候选和球心携带相同帧号。

第一轮 H2C 发送左右搜索图，FPGA 返回候选框、面积和位置。RK 根据这一帧的候选与跟踪预测生成一对局部图，第二轮 H2C 发送局部图，FPGA 返回左右球心与形状统计。两轮数据使用独立队列；下一帧搜索、上一帧球心和更早帧的三维计算可以流水运行。FPGA 通过 FIFO 与 `valid/ready` 控制数据流，RK 按帧号取回原图和处理结果。

程序按候选优先级为当前球选择一对局部图。多个目标有歧义时先结合预测、极线关系和 AI 身份排序，再安排补充局部图。图像帧号、ROI 原点和模型输出的坐标映射作为首周联调的共同字段；具体二进制布局由相关模块负责人评审后确定。

### 2.4 FPGA 搜索球可能出现的位置

搜索流水线采用 **3×3 高斯平滑 → 同侧帧差 → 阈值二值化 → 3×3 开闭运算 → 8 邻域连通域统计**。先用 OpenCV 写相同算法的参考程序，再把逐像素运算转换为 RTL。现有 `fpga/rtl/afh03_image/` 的行缓存、帧信息和流控结构作为基础，帧差、形态学、连通域及球心模块在这套结构上补充。[R6～R8]

高斯平滑使用权重为 1、2、1 的可分离 3×3 核，二维权重和为 16，通过加法与右移完成，减小像素噪声。帧差比较当前平滑图和同一眼上一帧平滑图，取亮度差绝对值；差值超过运动阈值时设为前景。运动阈值初始取 12 个灰度级，后续随补光和背景调整。左右前帧分别存储，图像边缘采用复制邻边的处理方式。

二值图先做一次 3×3 开运算去掉孤立噪点，再做一次 3×3 闭运算连接小断裂。连通域采用逐行游程标记：把同一行连续前景合为一段，合并与上一行相邻或斜相邻的段，累计面积、坐标和边界框。完整区域输出后，按面积、宽高比、预测距离排序。初始保留每眼最多 8 个候选；球在搜索图中的直径初始按约 6～20 像素组织尺寸窗口，具体范围结合机位调整。帧差中的旧位置和新位置都可能形成候选，后续在当前原图中确定球心。

最高点附近运动减弱时，RK 仍按跟踪预测发送该帧局部图，FPGA 持续测量球心。启动阶段及目标重捕获时，NPU 对发球区域识别球，提供搜索起点；搜索流水线则每帧持续工作。这样帧差负责快速发现运动，预测窗口负责保持连续测量，AI 提供身份信息。

### 2.5 生成左右局部图并由 FPGA 测量球心

RK 把搜索候选映射回 1280×720 原图，结合上一帧球心预测选定局部图中心。左右候选先通过标定参数做点坐标校正，按极线方向、球尺寸相近和预测位置配对；极线约束的含义是，同一个球在两张校正图中应处在近似相同的行。以同一个 `pair_id` 从两张**原始灰度图**裁出左右各 256×256 ROI。越出画面的部分补齐，并附实际有效范围。

局部图保留原图的像素几何关系。RK 随任务传入每眼 ROI 的原点和候选所在的小窗口；在候选附近约 64×64 区域统计灰度直方图，用 Otsu 法求局部阈值，结合候选与周围背景的亮度确定亮球或暗球极性。这个步骤提供阈值参数，精细分割与球心计算由 FPGA 完成。[R7]

FPGA 对局部图执行 3×3 平滑、局部阈值分割和一次 3×3 闭运算，再统计 8 邻域连通域。结合候选中心、面积、宽高比和前一帧尺寸选定球区域。对选中区域累计前景像素数 N、横坐标和与纵坐标和，分别除以 N 得到二值质心；除法在区域结束后执行，输出保留小数的定点坐标。区域形状、有效像素数和边界接触情况随球心返回。[R9]

同时用 3×3 Sobel 算子提取局部边缘，统计球周围的边缘完整性与对称性，作为区域选择和观测质量的辅助量。[R23]主测量采用二值质心；PC 参考程序可用轮廓圆拟合分析局部分割偏差。RK 收到球心后加上 ROI 原点，恢复左右原图坐标。处于遮挡阶段的图像观测与跟踪预测在结果中分别标注。

### 2.6 训练并部署 YOLOv8n 三类检测模型

模型固定为 **YOLOv8n 检测版**，从 `yolov8n.pt` 预训练权重开始微调，类别为 `ball`、`hand`、`racket`。n 表示小规模版本。它给出目标框和类别分数，用于告诉系统“哪个区域是球、附近是否有手或球拍”；最终三维坐标使用 FPGA 测出的左右球心。[R10、R11]

采集本项目相机的真实发球画面，分别标注球、可见手部和球拍的矩形框，加入握球、离手、顶点、遮挡、触拍、亮背景和运动模糊样例。训练图同时包含发球区域和球附近的上下文裁块。按人员和拍摄场次划分训练、验证与测试集合，同一段视频及左右对应图保持在同一组。三个关键事件另做帧区间标注，用于轨迹与事件逻辑。

输入固定为 640×640、三通道。灰度图复制为三个相同通道；矩形上下文图按比例缩放，并用灰度值 114 补到方形，保存缩放比例和补边。优先取原图中的发球区域或球周围上下文，保留小球的像素尺寸。初始训练配置为输入 640、100 轮、batch 16，显存不足时调整 batch；数据增强采用亮度变化、轻微模糊、平移和尺度变化。训练与导出使用同一份 Rockchip 适配 YOLOv8 代码并固定提交版本。训练输出 `best.pt`，保留三类名称与预处理配置。[R12]

部署采用 **Rockchip 适配的 YOLOv8 导出工具 → ONNX → RKNN Toolkit2 → RK3576 NPU**。使用 `airockchip/ultralytics_yolov8` 中的 RKNN 优化导出路径，将本项目权重导出为与 Model Zoo 后处理相配的 ONNX。RKNN 配置目标为 `rk3576`，以真实灰度复制图作为 INT8 校准数据，生成 `.rknn`；归一化统一为均值 0、标准差 255，预处理与图中运算合计执行一次归一化。[R13、R14]

RK 端采用 Model Zoo 的 C++ 推理和后处理框架，把类别数与标签表改为 3 类，并按导出张量完成框解码、DFL 后处理和非极大值抑制。非极大值抑制用于合并同一目标的重复框。检测分数与重叠阈值可先取 0.25、0.45 作为调参起点，再把模型框恢复到原图坐标。模型和标定版本与帧号一同保存。[R15]

NPU 初期安排约 20～30 次/秒的总调用预算，主要识别左眼发球上下文，右眼身份歧义时共享这项预算。每次调用绑定其输入 `pair_id`；较早帧的 AI 结果先用于更新轨迹身份，再预测到当前帧。FPGA 保持 60 对/秒的图像任务节奏，AI 以并行队列提供类别与重捕获提示。

### 2.7 从左右球心求出三维位置

RK 把左右原图球心送入 `undistortPoints`，结合 `stereoRectify` 的旋转与投影矩阵，将两个点转换为校正坐标。这里进行点坐标变换，局部图继续采用原图像素，减少整帧重映射。随后用 `triangulatePoints` 与左右投影矩阵求齐次三维点，除以其第四个分量得到左眼校正坐标系中的位置，再通过相应旋转与相机到世界坐标变换得到米制世界球心。[R3]

每个点保留 `pair_id`、帧时间、左右像素球心、世界坐标和图像质量。左右同一球的关系结合极线距离、球大小、NPU 身份和上一帧位置选择。相机方向与世界坐标转换分开保存，避免把沿镜头方向的深度与竖直高度混在一起。

跟踪采用单球卡尔曼滤波，状态为三维位置和速度，帧间隔取本次相邻帧时间；自由飞行阶段在预测中加入竖直重力项。新三维观测更新轨迹，短暂遮挡时预测下一帧左右位置，并反投影到图像供 ROI 调度。触拍后重新估计运动状态。原始测量点、滤波点和预测点分别保存，轨迹拟合主要使用实际观测。[R16]

### 2.8 计算离手点最高点和触拍点

事件处理采用“持球准备 → 上抛 → 到达顶点 → 下落 → 触拍”的状态顺序。持球阶段由球和手框邻近确定；球与手开始分离，且连续观测表现为向上运动时进入上抛。离手时刻由“最后一帧仍贴近手”与“第一帧已分离”之间的时间区间表示，再结合短自由飞行段插值求离手球心。手框提供辅助区域，球的运动变化和相邻原图一起用于判断分离。

对离手到触拍前的自由飞行点，使用加权最小二乘拟合：横向和纵向位置随时间线性变化，竖直位置随时间作二次变化。权重来自左右球心与几何观测质量；用迭代重加权减小少量异常点的影响。拟合时以离手附近的一帧作为时间零点，先求三个方向的曲线系数；竖直曲线的导数为零时得到顶点时刻，再代入三条曲线得到最高点三维位置。用这一段的上升与下落观测共同求顶点，可把最高点估计到两个采样帧之间。抛球高度为最高球心的世界 Z 减离手球心的世界 Z；上抛方向由水平位移、水平速度和竖直上升共同描述。

触拍结合球与球拍框的接近、轨迹折点及触拍前后速度变化。以最接近球拍并发生运动变化的邻近帧形成时间区间，触拍前后的轨迹分别拟合，保存触拍球心估计。三个关键点分别附左右局部图、相邻帧和对应三维片段，便于回看其来由。发球上升至少 16 cm 的规则依据 ITTF 资料，在界面中与本次测得高度一同显示。[R17]

## 3 结果呈现

显示左右原图中的球心、手框和球拍框，以及与时间对应的三维轨迹。重点列出离手、最高点、触拍的时间和位置，显示抛球高度与方向。回放时可逐帧查看搜索候选、左右 ROI 和球心结果，直观看到 FPGA 的各级处理如何产生三维观测。

发球记录保存关键点附近图像、轨迹数据、标定和模型版本、曝光设置及帧号。软件参考程序与 FPGA 使用相同的算法和像素配置，方便实现阶段定位问题和调整参数。人员职责与一个月时间安排沿用独立分工文档。

## 附录 A 可行性分析与理论预算

### A1 接口与模块资料

AFH03 的高速相机接入点为 J4 USB3 OTG0 Type-C；板内 RK 与 FPGA 连线为 PCIe1。J4 使用 USBDP PHY，PCIe1 使用 Combo PHY1，分别具有硬件通路。手册对另一组 USB 与相关 Hub 的复用关系有说明，调试安排 UART 与有线网，显示使用 HDMI。RK 配置 J4 的 USB 主机角色、5 V 供电和支持 5 Gb/s 的 C 至 C 数据线。PCIe 预算采用 2.0×1。[R18、R19]

本方案固定按 2560×720@60 YUY2 设计。用户商详给出这一模式；厂家同型号旧网页将 MJPEG 与 YUY2 的帧率分开，YUY2 表中列 5 fps，当前商详列 60 fps。这里保留资料版本差异，供落实所购固件参数时参考。客户确认的同步与手动曝光用于本方案配置。[R1、R22]

### A2 带宽与存储

按十进制 MB、有效像素纯载荷计算，拼接宽度已经包含两眼。YUY2 每像素 2 字节，RK 提取亮度后每像素 1 字节；协议、行填充与复制开销另计。[R4]

| 数据流或缓存 | 计算方式 | 理论值 |
| --- | --- | ---: |
| USB YUY2 拼接图 | 2560×720×60×2 | 221.184 MB/s |
| RK 双目 GRAY8 | 2×1280×720×60 | 110.592 MB/s |
| 双路搜索图 H2C | 2×640×360×60 | 27.648 MB/s |
| 每帧一对局部图 H2C | 2×256×256×60 | 7.86432 MB/s |
| PCIe H2C 合计 | 搜索图加一对局部图 | 35.51232 MB/s |
| FPGA 前帧读写 | 两眼搜索图读一次写一次 | 55.296 MB/s |
| RK 8 对 GRAY8 | 8×2×1280×720 | 14.7456 MB |
| 8 个 YUY2 拼接帧 | 8×2560×720×2 | 29.4912 MB |
| 8 对缓存时长 | 8÷60 | 133.33 ms |

USB3 5 Gb/s 经 8b/10b 编码后的数据上界约 500 MB/s，YUY2 纯载荷约占 44.2%。PCIe 2.0×1 的单方向编码后上界约 500 MB/s，本方案 H2C 纯载荷约占 7.1%。因此像素预算处于理论带宽范围内；总延迟还包含候选返回、ROI 生成、DMA 和三维计算。多个局部图按额外数量增加预算。[R20、R21]

RK 的 2 GB LPDDR4X 分配给采集缓冲、原图环、显示和 NPU。FPGA 的 256 MB DDR3L 保存左右前帧，双目一对搜索图共 0.4608 MB，双缓冲共 0.9216 MB；平滑与形态学行缓存、局部图和区域统计表使用片上 RAM。ROI 保留至阈值分割和统计完成，搜索帧与 ROI 的读写采用独立地址区。[R18]

每秒双路搜索共 27.648 Mpixel，一对局部图共 7.86432 Mpixel。按搜索一遍、ROI 一遍估计约 35.51232 Mpixel/s；ROI 若缓存后重复扫描，增加相应遍数的局部图流量。以一像素/周期、100 MHz 为流水线设计起点，可在左右图和 ROI 之间时分调度。行缓存、逐像素加法/比较和区域结束后的少量除法适合硬件实现；DDR 控制器、PCIe DMA 与连通域表一同纳入最终资源安排。

### A3 空间分辨率与时间采样

以镜头 2.1 mm、像元 3 μm、原生像素输出为估算条件，像素焦距约为 700。1.5 m 处 40 mm 球的直径约 18.7 像素，2.0 m 处约 14 像素；搜索图缩小后约为 9.3 和 7 像素，因此原图局部球心测量保留了更多空间信息。[R1、R2]

平行双目的简化深度关系为焦距乘基线再除视差。基线为 0.18 m、距离为 1.5 m 时，1 像素视差偏差对应约 17.9 mm 光轴深度变化。这个值用于分析焦距、基线与像素球心的关系；正式三维计算采用本机标定矩阵，竖直高度再由世界坐标得到。[R3]

60 fps 相邻帧间隔为 16.67 ms，速度为 2 m/s 时帧间位移约 3.3 cm。理想竖直抛物线在最高点附近取最近采样点，最大高度欠采样约为 0.34 mm；这个数字只描述理想顶点的时间离散误差，空间定位、离手时刻和遮挡另有影响。本方案以中间观测拟合最高点，离手和触拍保存邻近帧时间区间，符合三个关键点与简单飞行段的处理方式。

### A4 算法与部署依据

OpenCV 提供标定、点坐标校正、三角测量和卡尔曼滤波工具；高斯平滑、阈值、形态学与区域矩已有公开参考实现。YOLOv8n 在 Rockchip Model Zoo 中有 RK3576 示例，配套源码给出了导出、INT8 转换和 C++ 后处理路径。本方案将这些通用工具组合成双目球心测量链路，自定义球手拍数据、ROI 映射与关键点逻辑。[R3、R6～R16]

上面的带宽、像素尺寸与处理率是理论设计值。实现阶段若某个环节的效果需要改善，可调整阈值、候选尺寸、曝光、训练样本和流水调度；保留同一帧原图与各级结果，便于比较调整前后的变化。
