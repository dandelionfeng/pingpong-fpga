# AFH03 与 USB 同步双目乒乓球发球测量方案

版本：2026-10-04 无硬件 PC 算法闭环版。从2026年10月4日起按暂无任何实物开展开发，目标10月12日前完成PC算法与接口验收，拿到硬件后按清单迁移。总体准备周期保留至10月28日；硬件阶段按实际到货日D排期。

## 1 先说清楚这条路线

选用汇博视捷 HBVCAM-W2307-2 V11 系列的双 OV9281 USB3 模组，镜头选择标称 72°、3.6 mm 焦距的手动调焦版本。摄像头模组双目已同步、支持手动曝光；经 AFH03 的 RK3576J J4 高速 Type-C 口，以 YUY2 格式输出 2560×720 左右拼接图，每秒 60 fps，每眼 1280×720。左右镜头用刚性支架固定，光心基线为 150～200 mm。初期机位距目标约 1.5 m，以两眼共同覆盖持球、最高点和触拍区域调整距离与俯仰；调焦后锁紧镜头。较窄视角有助于让同距离的球占更多像素，配合短曝光和补光保持轮廓清晰；标称视角、焦距和实际读出范围随镜头配置记录。[R1、R2]

RK 保存左右灰度原图，将每眼 640×360 搜索图经板内 PCIe1 交给安路 PH1A90SEG324 FPGA。FPGA 一次完成平滑、帧差、阈值和形态学运算，返回两眼的运动掩膜；掩膜就是标出可能运动区域的黑白图。RK 从掩膜筛选候选，在同一帧原图中取左右各 256×256 局部图并求球心，再利用标定参数计算三维位置。NPU 继续运行 YOLOv8n 三类检测模型，提供身份、遮挡和事件提示。最终得到离手点、最高点、触拍点，以及抛球高度、方向和简洁的三维轨迹。

正式主链路为“相机 → RK灰度与缩图 → FPGA运动掩膜 → RK局部球心、三维与关键点”，AI并行。当前先以文件输入、CPU整数前端和PC三类模型运行同一套后续程序，RTL在PC离线仿真；全部输入与中间结果可保存对照。本版把到货前目标设为可复现的 PC 算法与接口验收：整数参考、RTL、局部测量、几何、事件、PC 三类模型及异步调度分别有输入和结果。合成数据通过只证明受控场景正确；真实相机标定、同步、域适配、DDR/PCIe、RKNN 板端效果与性能在到货后验收。以下日期为执行目标，各项结果由实施日志填写。

## 2 从相机到三个关键点的具体步骤

### 2.1 固定机位并完成双目标定

先安装相机，让两眼都能看到发球手、上抛空间和球拍。保持镜头位置、光心间距和焦点固定，采用稳定补光。曝光初始按约 0.5 ms 设置，曝光与增益采用手动控制；程序按相机控制项的实际单位填写参数。启动采集时固定 2560×720、60 fps、YUY2，后续训练与运行都使用这组分辨率。

使用内角点为 9×6 的棋盘格标定板，实测方格边长并以米输入。拍摄约 25～40 对同步图，覆盖中心、边缘、不同距离和倾斜角度。OpenCV findChessboardCornersSB 提取角点，分别用 calibrateCamera 求两眼内参和畸变，再用 stereoCalibrate 配合 CALIB_FIX_INTRINSIC 求相机间的旋转与平移；stereoRectify 生成校正旋转和左右投影矩阵。保存内参、畸变、相机相对位姿、投影矩阵与标定版本。[R3]

72°镜头的轻微径向和切向畸变可以通过棋盘格标定与软件校正处理。先用普通针孔模型估计 k1、k2、k3、p1、p2，运行时按 2.7 的 undistortPoints 校正左右球心，再做三角测量；观察校正画面时使用 initUndistortRectifyMap 与 remap。原图搜索和局部测量保留原始像素，几何校正集中在点坐标。换镜头或改变焦点后重新标定，B 将新版本交给 A/C；调焦、曝光和补光负责轮廓锐度。[R3]

在球台上建立世界坐标：X 沿台面横向，Y 沿球台长度方向，Z 竖直向上，单位为米。取若干已知三维位置的棋盘格角点，使用 solvePnP 得到世界到左相机的旋转 Rcw 与平移 tcw，再求逆得到相机到世界的变换：X世界=Rcwᵀ(X相机−tcw)。这样程序算出的“向上”对应真实竖直方向，抛球高度就是世界坐标中的高度变化。标定与世界坐标参数随相机配置一同保存。[R3]

PC先做：用OpenCV成对棋盘样例跑角点、标定和保存/加载；再用多个棋盘姿态的独立合成图检验重投影及世界变换。公开图方格真实尺寸未知时仅验证方格单位，最终米制内外参在实际相机锁焦后重做。复制/平移单目图不能提供真实双目标定证据。[R30]

### 2.2 在 RK 端采集并拆分左右灰度图

采集程序采用 Linux V4L2 的 C++ 接口。设置 V4L2_PIX_FMT_YUYV，即 Linux 中与 YUY2 对应的格式，申请 MMAP 缓冲区，按 QBUF → STREAMON → DQBUF → 处理 → QBUF 循环读取拼接帧。每个完整拼接帧分配一个 pair_id，同时保留驱动序号、帧时间、像素格式和行步幅；左右图沿用同一个 pair_id。[R4、R5]

Windows PC 也可以使用这款 UVC 相机。系统 UVC 驱动支持 YUY2，OpenCV 可通过 CAP_DSHOW 或 CAP_MSMF 调用；在 PC 上选择 USB3、目标模式和手动曝光后，可完成取图、标定与回放。商详的 Windows 支持指相机接电脑的兼容性。AFH03 整机继续使用配套 Linux 镜像，衔接 V4L2、PCIe 驱动和 RKNN Runtime；团队成员可在 Windows 电脑准备软件和处理 A 提供的文件。训练在 PC 进行，RKNN 转换沿用 Toolkit2 支持的 PC Linux 环境。[R4、R5、R27]

YUY2 的两个相邻像素按 Y0 U Y1 V 排列。程序逐行按驱动返回的步幅读取，每个像素取其中的 Y 字节，保留实际 8 位亮度；拼接图横向第 0～1279 列作为左眼，第 1280～2559 列作为右眼，得到两张 1280×720 GRAY8 图。相机左右排列在配置中固定。提取出的 Y 值贯穿图像处理与训练预处理。[R4]

RK以8对左右灰度图组成环形缓存，图像从入队到局部图裁切和显示结束保持引用；异步检测额外持有必要上下文裁块或有容量上限的引用。每眼2×2平均得到640×360搜索图，取整起点拟为四像素和加2后右移2位，A/B评审后固定。中心映射u原=2u搜索+0.5、v原=2v搜索+0.5，框边界按覆盖范围映射。先用C++，RGA插值若改变则重做像素及坐标验收。[R24]

PC先做：FileFrameSource逐行读取带stride的YUY2，或读成对GRAY8与manifest；模拟采样时间和pair_id，输入参数错误/截断明确拒收。原Y值、环缓存、缩图、ROI和保存代码在PC/RK共用；V4L2只负责设备输入适配。

### 2.3 将双路搜索图一次送入 FPGA

RK 为主机，FPGA 为 PCIe 端点，使用板内 PCIe1 的双向 DMA。主机送入 FPGA 的方向称 H2C，FPGA 返回主机的方向称 C2H。每个任务带 pair_id、左右标识、宽高、步幅、任务类型和配置版本。H2C 发送两张连续 GRAY8 搜索图，C2H 返回同帧的两张掩膜，继续携带左右标识和原始帧号。

主路径每对图像安排一次 H2C 提交和一次 C2H 完成通知，RK 收到掩膜后直接在本机裁切原图和求球心。掩膜拟按 1 bit/像素打包：每行 640 像素对应 80 字节，每对掩膜共 57,600 字节；RK 按约定的位顺序展开为 0/255 图。下一帧 FPGA 处理、上一帧局部测量和更早帧三维计算用独立队列流水运行。

DMA 缓冲区从固定池复用，采用驱动完成事件或阻塞等待接收结果，等待期间把 CPU 留给其他任务。FPGA 用 FIFO 与 valid/ready 控制输入、前帧读写和输出背压。采集、处理、NPU 和界面分开调度，显示按 60 fps 组织，测量按相机 60 对/秒设计。发生任务跳帧时记录 pair_id 和实际时间间隔；帧差参考同一眼最近一张参与处理的图。新增掩膜消息影响 RK 解包和 FPGA 输出，模型输入继续使用 640×640，三维世界系继续沿用原约定。[R28]

PC先做：CpuMotionBackend通过同一逻辑提交/完成接口输出Mask，模拟延迟、乱序、超时、背压及配置失配。三类后端分别管理输入、运动前端和检测；描述符/位序当前待A/B评审。mock通过只说明软件调度，正式PCIe驱动、缓存一致性和持续带宽另验。

### 2.4 FPGA 连续生成双路运动掩膜

FPGA 搜索流水线采用 3×3 高斯平滑 → 同侧帧差 → 阈值二值化 → 3×3 开运算 → 3×3 闭运算 → 掩膜打包。开、闭运算各包含两级基本运算，整个像素前端共七级计算。整数软件参考与 RTL 同步实现，使用同一组图像、参数和边界规则核对各级输出。现有 fpga/rtl/afh03_image/ 的行缓存、帧信息和流控结构作为基础，补充帧差、四级形态学和打包模块。[R6～R8]

高斯平滑使用权重为 1、2、1 的可分离 3×3 核，二维权重和为 16。中间加法保留足够位宽，最后按“加 8 后右移 4 位”舍入到 8 位，软件参考采用同样规则。帧差比较当前平滑图和同一眼前帧平滑图，取亮度差绝对值；超过运动阈值时设为前景。阈值初始取 12 个灰度级，随后按补光和背景调整。左右前帧分区保存，首帧先建立参考；各级边缘采用复制邻边，行列坐标随有效像素一起传递。

二值图先用 3×3 腐蚀再膨胀，去掉孤立噪点；随后用 3×3 膨胀再腐蚀，连接小断裂。对二值像素，腐蚀对应九个邻点的逻辑与，膨胀对应逻辑或。四级模块各保留少量行缓存，前一级输出即送往后一级；流水线填满后，各级可以同时处理不同像素。左右图先共用一套流水线按帧时分处理，采用独立前帧地址和状态。完成掩膜后，连通域筛选在 RK 端执行。

最高点附近运动减弱时，RK 仍按跟踪预测在该帧原图中生成局部图并测量球心。启动阶段及目标重捕获时，NPU 对发球区域识别球，提供搜索起点；FPGA 运动前端每帧持续工作。这样运动掩膜负责缩小搜索范围，预测窗口负责保持连续测量，AI 提供身份信息。

PC先做：A完成七级C++整数参考，B独立复核，A/B分摊前三/后四级RTL；testbench逐级逐像素及打包字节比较，加入左右时分、valid/ready随机停顿、首帧/复位/短帧。左右独立reference_id，只有完整成功帧更新参考。先用存储模型仿真，再等AFH03验真实DDR3L控制器。

### 2.5 在 RK 局部图中测量左右球心

RK 先用 connectedComponentsWithStats 对掩膜做 8 邻域连通域统计，取得面积、边界框和粗质心。按面积、宽高比和预测距离排序，每眼初始保留最多 8 个候选，球在搜索图中的直径先按约 6～20 像素组织尺寸窗口。帧差会同时出现球的新旧位置，精细测量使用当前原图。候选映射回 1280×720 原图后，结合点校正、极线距离和球尺寸配对；同一个球在两张校正图中应位于近似相同的行。按同一 pair_id 裁出左右各 256×256 ROI，越出画面的部分补齐并附有效范围。[R3、R9]

局部图保留原图的像素几何关系。在候选附近约 64×64 区域统计灰度直方图，用 Otsu 法求局部阈值，并结合背景亮度确定亮球或暗球极性。RK 对 ROI 做 3×3 平滑、局部阈值分割和一次 3×3 闭运算，再统计连通域；结合候选中心、面积、宽高比和前一帧尺寸选出球区域。每对局部图共 131,072 像素，约为两眼原图的 7.1%，这一部分由 C++ 和 OpenCV 实现，与 FPGA 大范围搜索前端分工协作。[R7～R9]

对选中球区域，用 moments 累计前景面积 m00、横坐标矩 m10 和纵坐标矩 m01，计算 u=m10/m00、v=m01/m00，并保留小数坐标；原图球心再加上 ROI 原点。返回面积、宽高比、是否接触 ROI 边界和亮度差等质量量。观测点、滤波点和遮挡阶段的预测点分别标注。先形成稳定的二值质心链路，再根据分割偏差加入轮廓圆拟合。[R9]

局部 Sobel 边缘分析用于观察球轮廓的完整性与对称性，帮助处理背景干扰或部分遮挡。[R23] 局部平滑、分割、连通域和图像矩由 RK 实现，FPGA 持续提供双路运动掩膜；参数调整和轮廓圆拟合围绕同一条硬件测量链路进行。

PC先做：用受控亮/暗球、运动干扰、边缘、遮挡与顶点静止序列检验候选、ROI/Otsu/moments；保存中心误差与质量拒收原因。实际公开图用于观察背景和轮廓问题；独立真值只用于评分，Sobel/圆拟合等优化在主链路通过后增加。

### 2.6 训练并部署 YOLOv8n 三类检测模型

模型固定为 YOLOv8n 检测版，从 yolov8n.pt 预训练权重开始微调，类别为 ball、hand、racket。n 表示小规模版本。它给出目标框和类别分数，用于告诉系统“哪个区域是球、附近是否有手或球拍”；最终三维坐标使用原始局部图中测得的左右球心。[R10、R11]

采集本项目相机的真实发球画面，分别标注球、可见手部和球拍的矩形框，加入握球、离手、顶点、遮挡、触拍、亮背景和运动模糊样例。训练图同时包含发球区域和球附近的上下文裁块。按人员和拍摄场次划分训练、验证与测试集合，同一段视频及左右对应图保持在同一组。三个关键事件另做帧区间标注，用于轨迹与事件逻辑。

输入固定为 640×640、三通道。灰度图复制为三个相同通道；矩形上下文图按比例缩放，并用灰度值 114 补到方形，保存缩放比例和补边。优先取原图中的发球区域或球周围上下文，保留小球的像素尺寸。初始训练配置为输入 640、100 轮、batch 16，显存不足时调整 batch；数据增强采用亮度变化、轻微模糊、平移和尺度变化。训练与导出使用同一份 Rockchip 适配 YOLOv8 代码并固定提交版本。训练输出 best.pt，保留三类名称与预处理配置。[R12]

部署采用 Rockchip 适配的 YOLOv8 导出工具 → ONNX → RKNN Toolkit2 → RK3576 NPU。使用 airockchip/ultralytics_yolov8 中的 RKNN 优化导出路径，将本项目权重导出为与 Model Zoo 后处理相配的 ONNX。RKNN 配置目标为 rk3576，以真实灰度复制图作为 INT8 校准数据，生成 .rknn；归一化统一为均值 0、标准差 255，预处理与图中运算合计执行一次归一化。[R13、R14]

RK 端采用 Model Zoo 的 C++ 推理和后处理框架，把类别数与标签表改为 3 类，并按导出张量完成框解码、DFL 后处理和非极大值抑制。非极大值抑制用于合并同一目标的重复框。检测分数与重叠阈值可先取 0.25、0.45 作为调参起点，再把模型框恢复到原图坐标。模型和标定版本与帧号一同保存。[R15]

NPU 初期安排约 20～30 次/秒的总调用预算，主要识别左眼发球上下文，右眼身份歧义时共享这项预算。每次调用绑定其输入 pair_id；较早帧的 AI 结果先用于更新轨迹身份，再预测到当前帧。运动前端与局部球心按 60 对/秒设计，AI 以并行队列提供类别与重捕获提示。

PC先做：用许可公开图补齐ball/hand/racket标签，按人员/场次分组，训练真实三类基线并逐图对照PT/适配ONNX及C++后处理；显式回放类别框另验下游。可在Toolkit2支持的PC Linux环境提前转换rk3576 RKNN。公开图量化仅为初版，真实灰度补训/校准和NPU Runtime/驱动及INT8差异在到货后验收。[R11、R14]

### 2.7 从左右球心求出三维位置

RK用undistortPoints结合stereoRectify的R1/R2及P1/P2把左右原图球心变成校正像素，再用triangulatePoints求齐次点。除以第四分量得左眼校正坐标Xrect，先以Xc=R1ᵀXrect回到左相机，再以X世界=Rcwᵀ(Xc−tcw)求米制世界坐标。检查正深度、低视差、极线与重投影误差；无效观测进入明确拒收状态。[R3]

每个点保留 pair_id、帧时间、左右像素球心、世界坐标和图像质量。左右同一球的关系结合极线距离、球大小、NPU 身份和上一帧位置选择。相机方向与世界坐标转换分开保存，避免把沿镜头方向的深度与竖直高度混在一起。

跟踪采用单球卡尔曼滤波，状态为三维位置和速度，帧间隔取本次相邻帧时间；自由飞行阶段在预测中加入竖直重力项。新三维观测更新轨迹，短暂遮挡时预测下一帧左右位置，并反投影到图像供 ROI 调度。触拍后重新估计运动状态。原始测量点、滤波点和预测点分别保存，轨迹拟合主要使用实际观测。[R16]

PC先做：独立投影已知三维点到两相机，覆盖非零姿态/畸变，检验米制世界系往返；再加像素噪声、错配、丢帧和遮挡，验证实际dt、质量拒收与重捕获。预测点只用于搜索/显示，拟合以实际观测为依据；合成误差不能替代真实静态量距。

### 2.8 计算离手点最高点和触拍点

事件处理采用“持球准备 → 上抛 → 到达顶点 → 下落 → 触拍”的状态顺序。持球阶段由球和手框邻近确定；球与手开始分离，且连续观测表现为向上运动时进入上抛。离手时刻由“最后一帧仍贴近手”与“第一帧已分离”之间的时间区间表示，再结合短自由飞行段插值求离手球心。手框提供辅助区域，球的运动变化和相邻原图一起用于判断分离。

对离手到触拍前的自由飞行点，使用加权最小二乘拟合：横向和纵向位置随时间线性变化，竖直位置随时间作二次变化。权重来自左右球心与几何观测质量；用迭代重加权减小少量异常点的影响。拟合时以离手附近的一帧作为时间零点，先求三个方向的曲线系数；竖直曲线的导数为零时得到顶点时刻，再代入三条曲线得到最高点三维位置。用这一段的上升与下落观测共同求顶点，可把最高点估计到两个采样帧之间。抛球高度为最高球心的世界 Z 减离手球心的世界 Z；上抛方向由水平位移、水平速度和竖直上升共同描述。

触拍结合球与球拍框接近、轨迹折点及前后速度变化，用邻近观测形成时间区间；保存相邻帧、局部图与三维片段。缺少手/拍证据或可靠观测时输出不可确定，取消发球不强行生成触拍。界面可显示16 cm参考线及测量区间；阈值附近需结合不确定度保留待复核状态，判罚阈值经负责人评审后固定。[R17]

PC先做：分别测轨迹级拟合与图像/语义级事件。合成上抛XYZ只验证拟合；完整事件另输入有来源帧号的hand/racket观测框和可见性，真值离手/触拍只进评分器。测试正常、未触拍、缺手/拍、遮挡和迟到结果，区间及unknown路径均需通过。

## 附录 A 可行性分析与理论预算

### A1 接口与模块资料

AFH03 的高速相机接入点为 J4 USB3 OTG0 Type-C；板内 RK 与 FPGA 连线为 PCIe1。J4 使用 USBDP PHY，PCIe1 使用 Combo PHY1，分别具有硬件通路。手册对另一组 USB 与相关 Hub 的复用关系有说明，调试安排 UART 与有线网，显示使用 HDMI。RK 配置 J4 的 USB 主机角色、5 V 供电和支持 5 Gb/s 的 C 至 C 数据线。PCIe 预算采用 2.0×1。[R18、R19]

本方案固定按所选 72°、3.6 mm 手动调焦模组的 2560×720@60 YUY2 模式设计，双目同步与手动曝光沿用客服确认。厂家同系列旧网页的 YUY2 表列 5 fps，用户提供的当前商详列 60 fps；该差异保留在资料附录，镜头、固件模式和曝光控制按所购版本记录。72°和3.6 mm 分别是镜头标称视角与物理焦距，像素焦距和畸变由本机标定给出。[R1、R22]

米联客 AFH03 官方配套目录列有 MIPI—ISP—PCIe 链路实验，可作为板内 PCIe 工程的参考。官方演示的图像方向是 FPGA 前端向 RK 传输；本方案还需要 RK 向 FPGA 送搜索图，因此起步阶段先准备双向 DMA、缓冲区一致性和完成通知。Linux 图像软件链路与这部分并行开发，图像算法接口按消息类型逐步接入。[R26]

按十进制 MB、有效像素纯载荷计算，拼接宽度已经包含两眼。YUY2 每像素 2 字节，RK 提取亮度后每像素 1 字节；协议、行填充与复制开销另计。[R4]

USB3 5 Gb/s 经 8b/10b 编码后的数据上界约 500 MB/s，YUY2 纯载荷约占 44.2%。PCIe 2.0×1 每方向编码后上界约 500 MB/s，主路径 H2C 纯载荷占约 5.5%，C2H 掩膜占约 0.7%；两个方向分别计算。若增加每帧一对 FPGA ROI 任务，H2C 合计为 35.51232 MB/s，占约 7.1%。这些比例用于载荷预算，DMA 与内存处理开销加入完整链路分析。[R20、R21]

RK 的 2 GB LPDDR4X 分配给采集缓冲、原图环、显示和 NPU。FPGA 的 256 MB DDR3L 保存左右前帧，一对搜索图共 0.4608 MB，前后双缓冲共 0.9216 MB。高斯与二值形态学的行缓存、DMA FIFO 和掩膜打包缓存使用片上 RAM。两眼共用一套流水线，Gaussian 采用加法与移位，二值形态学采用逻辑运算；资源安排重点包括 PCIe 端点、DDR 控制器、FIFO 和跨时钟域。局部测量由 RK 完成，表中的附加 ROI 传输量供扩展接口容量参考。[R18]

主路径每秒处理 27.648 Mpixel。以一像素/周期、100 MHz 为设计起点，两眼一对搜索图需 460,800 个有效像素周期，理想纯计算时间约 4.608 ms，相机周期为 16.67 ms。七级计算用独立硬件连续流水，填充、边缘补齐、DDR 等待和 DMA 背压另计；100 MHz 是时序设计目标。双眼共用一条流水线具有理论吞吐余量，RK 同时承担局部区域统计和后续几何运算。

### A3 空间分辨率与时间采样

72°先按镜头标称视角记录。若它指当前 1280×720 画面的水平视角，理想针孔模型的像素焦距约为 1280÷[2tan(36°)]=880.9；1.5 m 处画面覆盖约 2.18 m×1.23 m，40 mm 球直径约 23.5 像素，2.0 m 处约 17.6 像素。若 72°指该画面对角视角，则像素焦距约为 √(1280²+720²)÷[2tan(36°)]=1010.7，1.5 m 处球约 27.0 像素。在同为水平视角、相同距离与等比例读出的条件下，球像素直径比原 84°估算增大约 23.9%，相应视野收窄。商品视角与毫米焦距可能采用不同有效画幅口径，正式测量使用标定所得 fx/fy 与畸变；搜索图直径约为原图一半。[R3]

平行双目的简化深度关系为 Z=fB/d，f 为像素焦距，B 为米制基线，d 为视差。按 B=0.18 m、Z=1.5 m、水平 72°的 f=880.9 估算，1 像素视差偏差对应约 14.2 mm 光轴深度变化；按对角 72°的 f=1010.7 估算，约为 12.4 mm。该量用于分析视角、基线与球心坐标的关系；正式三维计算采用本机标定矩阵，竖直高度再由世界坐标得到。[R3]

60 fps 相邻帧间隔为 16.67 ms，速度为 2 m/s 时帧间位移约 3.3 cm。理想竖直抛物线在最高点附近取最近采样点，最大高度欠采样约为 0.34 mm；这个数字只描述理想顶点的时间离散误差，空间定位、离手时刻和遮挡另有影响。本方案以中间观测拟合最高点，离手和触拍保存邻近帧时间区间，符合三个关键点与简单飞行段的处理方式。

### A4 算法与部署依据

OpenCV 提供标定、点坐标校正、三角测量、卡尔曼滤波和局部图像测量工具；高斯平滑、阈值、形态学与图像矩均有公开参考实现。Rockchip Model Zoo 的 YOLOv8 示例列有 RK3576，并给出适配导出、INT8 转换和 C++ 后处理路径。本方案将 FPGA 运动前端直接融入双目测量链路，RK 与 NPU 承担局部几何和语义任务；整数软件参考、RTL 和板端程序并行开发，共享图像与接口语义。[R3、R6～R16]

### A5 FPGA 计算卸载与功耗的理论说明

理论工作量：双路搜索每秒共 27.648 百万像素，高斯、帧差、阈值和四级形态学共对应约 193.536 百万次“像素级阶段输出”；其中四级形态学约为 110.592 百万次。这是算法工作量的计数口径，CPU 指令数还受 SIMD、线程和算子融合影响。硬件模式把上述阶段从 CPU 移至 FPGA，CPU 继续承担缩图、DMA 管理、掩膜展开与后续测量。

流水线收益：各级计算同时处理不同像素，结果沿行缓存和 FIFO 向前传递，避免逐级把整帧中间图写回主机内存。在每级均能接受一像素/周期的模型下，七级串行需约 7N 个像素周期，流水线约需 N 加填充周期；这里 N 为一对搜索图的像素数。该结构说明并行流水线的理论优势，RK3576 的实际软件吞吐由其优化实现决定。

CPU 时间收益：设软件运动前端消耗 t前端 毫秒 CPU 时间，FPGA 模式新增的 DMA 提交、完成处理和掩膜展开合计为 t辅助，则每对图像可释放的 CPU 时间约为 t前端−t辅助。使用异步 DMA 和固定缓冲池有助于控制 t辅助。界面使用 getrusage 的用户态与内核态时间之和，除以实际处理的图像对数，展示每对图像占用的 CPU 毫秒；CPU 空闲等待与墙钟延迟分开统计。[R25]

比较方式：软件模式和 FPGA 模式使用同一段输入、同一算法、同一帧率目标、同一 NPU 调度和同一并发功能。CPU 软件采用正常优化的 C++ 和 OpenCV，实现像素精度、边界和输出功能一致；可以加入实际需要的片段保存、回放或多区域测量，并把这些功能同时应用到两种模式。这样增加的是作品功能，CPU 负载变化才能说明硬件卸载的作用。

功耗收益：CPU 像素计算和主机中间图访存减少，理论上可降低相应活动功耗；FPGA 内的图像寄存器采用时钟使能，有数据时更新。整板是否省电取决于节省的 CPU 与内存功率是否超过新增的 FPGA 与 PCIe 活动功率。可按“节省功率=CPU与主机内存减少量−FPGA与PCIe增加量”分析，并以“整板平均功率÷每秒完成的图像对数”定义每对图像能耗。本方案把 CPU 计算卸载作为直接收益，整板节能作为条件性收益，具体百分比留给后续记录。
