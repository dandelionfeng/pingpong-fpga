# UNIFIED_V3_LABEL_AUDIT — 标注完整性审计（本轮最重要的检查）

日期：2026-10-25

## 1. 问题定义

三个数据源是**分别标注**的，直接合并会让"没标注的类别"被当成背景：

| 数据源 | 帧数（train） | 标了什么 | **没标什么** |
| --- | --- | --- | --- |
| tabletennis（tt/tt2） | 2,110 | ball + racket | **hand** |
| bodyhands（bh） | 700（抽样） | hand | ball / racket |
| hand_pseudo（pp） | 400 | hand | ball / racket |
| hand_synthetic（sy） | 400 | hand | ball / racket |
| 负样本（bg/hn） | 300 | 无目标 | — |
| **BNDSTT 球帧（ps，本轮新增）** | **521** | ball（+ 本轮补的 hand 候选） | **racket** |

## 2. 逐类检查方法与结果

### 2.1 Ball（GT 是否过少 / 是否大量漏标）

| 检查 | 方法 | 结果 |
| --- | --- | --- |
| GT 总量 | 直接统计 | V2 训练集 **1,978 框**；本轮 +521 → **2,499 框** |
| 是否存在"有球但无球标注"的图 | 用 Ball 专项模型（V6R2, 960）在 hand 数据集上跑一遍，统计高置信球 | **见 §2.4 结论**：hand 数据集是近景手部图，球基本不可见或极小，未采用 |
| 新增帧的球标签可靠性 | 抽样目视（12 张拼图） | 球框落在发球手附近的球上，**可用**（`artifacts/unified_3cls_v3/visuals/v4_added_frames.jpg`） |
| 球尺寸 | 统计 | BNDSTT 域中位 ~34 px；tabletennis 19–31 px；均为小目标 |

**结论**：ball GT 从 1,978 提升到 2,499（+26.3%），且新增部分来自**部署域**（球馆发球）。
这是本轮能做的、最确定的 ball 数据改进。

### 2.2 Racket

| 检查 | 结果 |
| --- | --- |
| GT 总量 | 4,790 框（全部来自 tabletennis），本轮**未增加** |
| 是否存在"有拍但无拍标注"的图 | BNDSTT 球帧（521）中确实可能有球拍，但 Racket 专项在球馆远景下几乎不出框（此前实测 Match5 上 AP50 0.675，BNDSTT 域更差），**自动补标注不可靠 → 未补** |
| 球拍被误标为 hand？ | 未发现；两类来源不同，无交叉 |
| 框过松/偏移 | 未系统筛查；沿用源数据 |

**结论**：racket 本轮**没有新增数据**，只能靠训练改善；若训练没有提升，应如实报告。

### 2.3 Hand

| 检查 | 结果 |
| --- | --- |
| GT 总量 | V2 3,123 框 → 本轮 **3,698 框**（+575 来自自动候选） |
| 自动候选来源 | Hand 专项（`hand_v3_960`，已验证）在 521 张 BNDSTT 球帧上 conf ≥ 0.45 → 575 框 / 436 图 |
| 候选可靠性 | 抽样目视：绿框落在球员手/臂区域，合理；但**不是人工标注** |
| 状态标记 | manifest 里每行 `AUTO_ASSISTED_HAND_CANDIDATE`，**未经人工逐框确认** |

### 2.4 隔离与未采用

| 数据 | 处理 | 原因 |
| --- | --- | --- |
| BNDSTT 球帧的 racket | **不生成** | 专项模型在该域不可靠，强行补标注 = 引入噪声 |
| hand 数据集里的 ball/racket | **不生成** | 近景手部图，球/拍常不可见或极小；补了也多是误标 |
| tabletennis 帧的 hand | **不生成** | 广角远景，远处手部极小，自动标注不可靠 |
