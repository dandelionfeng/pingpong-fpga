日期：2026-10-26

## 1. 初始化策略

**不静默忽略错误**：逐张量比对名字 + 形状，只加载完全匹配的，并把未加载的部分逐项记账。

| 项 | 值 |
| --- | --- |
| 源权重 | `artifacts/runs/unified_3cls_v3b/weights/best.pt`（V3，3 类） |
| 目标 | `yolov8n_p2_3cls.yaml`（4 尺度检测头） |
| 保存的初始化 checkpoint | `artifacts/runs/p2_init_from_v3.pt` |
| 加载方式 | `load_state_dict(strict=True)`（先合并已匹配项，再整体严格加载）→ **不会静默丢弃** |

## 2. 迁移结果（实测）

| 指标 | 数值 |
| --- | --- |
| 目标张量总数 | 437 |
| **成功迁移张量** | **219（50.1%）** |
| **成功迁移参数** | **1,464,348 / 2,926,956 = 50.0%** |
| 检测头参数（保持随机初始化） | **36,992（1.3%）**，6 个张量 |
| 头部之外形状不匹配 | **45 个张量** |
| 源头中不存在 | **167 个张量** |

## 3. 未迁移部分是什么（逐类说明）

| 类别 | 张量数 | 说明 |
| --- | ---: | --- |
| 新增 P2 分支（neck 第 2/3/4 级） | ~167 | P2 配置比普通 yolov8n 多出一条自上而下的 P2 通路，**这些层在原网络里根本不存在** |
| 通道数变化的 neck 层 | 45 | 例如 `model.18.cv1.conv.weight`：源 `(128,192,1,1)` vs 目标 `(32,96,1,1)`。原因：P2 配置里 `model.18` 是 **P2 级 neck**（width 0.25 → 32 通道），而普通 yolov8n 的同序号层是更深一级（128 通道）。**属于层序错位，绝不能按序号硬套**，所以按形状拒绝 |
| Detect 头 | 6 | 4 个尺度 vs 3 个尺度，`cv2/cv3` 数量与前向通道都不同 → **整个头随机初始化** |

**结论**：backbone（layer 0–9，含 SPPF）几乎全部迁移；新增的 P2 neck 与检测头随机初始化。
这正是"加检测头"必然的代价，已在训练中通过 12 轮微调让它收敛。

## 4. 为什么不选官方 COCO 初始化

官方 `yolov8n.pt` 同样是**3 尺度**结构，迁移到 P2 时也会遇到同样的形状不匹配；
而本项目的数据是**灰度乒乓三分类**，与 COCO 差异极大。用 V3 初始化至少让 backbone 直接
适配了灰度乒乓特征。**选择已在报告中记录，便于复现**。
