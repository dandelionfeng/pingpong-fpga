# SMALL_BALL_AUGMENTATION_AUDIT — 尺度保护增强审计

日期：2026-10-26　对照：E0(V3) 的增强 vs E2 的尺度保护增强

## 1. 两套增强配置

| 参数 | E0 (V3) | **E2 (V6 尺度保护)** | 变化意图 |
| --- | ---: | ---: | --- |
| `mosaic` | 0.2 | **0.1** | 降低拼图概率（拼图会把球缩到约一半） |
| `close_mosaic` | 5 | 5 | 最后 5 轮关闭 mosaic |
| `scale` | 0.4 | **0.25** | 缩小随机缩放幅度 |
| `mixup` | 0.0 | 0.0 | 保持不用 |
| `degrees` | 5 | 5 | 保持适度旋转 |
| `fliplr` | 0.5 | 0.5 | 保持水平翻转 |
| `hsv_h` / `hsv_s` | 0 / 0 | 0 / 0 | 灰度数据不需要 |
| `hsv_v` | 0.4 | 0.4 | 保留亮度变化 |
| 输入 | Gray3 | Gray3 | 与部署一致 |

## 2. 小球在增强下的最坏情况（解析计算）

ultralytics 的 `scale` 参数表示随机缩放倍数区间 `[1-scale, 1+scale]`：

| 配置 | 缩放区间 | 12.2 px 的球最坏变成 |
| --- | --- | ---: |
| E0（scale 0.4） | [0.60, 1.40] | **7.3 px** |
| E2（scale 0.25） | [0.75, 1.25] | **9.2 px** |

→ 尺度保护把最坏情况从 7.3 px 提到 9.2 px（**+26%**），避免把球缩到 10 px 以下。

mosaic 的影响更大：4 图拼成 1 张时每张被缩到约 1/2，12.2 px 的球会变成 **~6 px**。
mosaic 概率从 0.2 降到 0.1，这类"极小样本"的曝光减半。

## 3. 实测结果：保护没有换来收益

| 指标 | E0 (V3) | E2 |
| --- | ---: | ---: |
| Ball Recall | **0.460** | 0.380 |
| Ball AP50 | **0.538** | 0.440 |
| Overall mAP50 | **0.627** | 0.589 |
| 实际训练轮数 | 15 | **10（早停）** |

**解读（不夸大）**：
1. 尺度保护本身没有让球更容易学，反而因为 **mosaic 减少 → 上下文多样性下降 → 早停更早（第 10 轮）**，
   整体指标下降；
2. 不能据此断言"尺度保护有害"，因为 E2 同时改了采样（1.2× 曝光）和 mosaic，且比 V3 少训 5 轮；
3. **可以确定的是：在现有数据上，靠"少缩小 + 多曝光"无法突破 Ball Recall。**
