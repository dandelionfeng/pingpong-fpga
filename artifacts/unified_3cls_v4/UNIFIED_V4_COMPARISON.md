## 3. 判读

| 问题 | 结论 |
| --- | --- |
| **Ball Recall 是否提升** | **没有**。V2 0.475 → V3 0.460 → V4 0.420（AP 口径）；部署阈值下 V2 0.520 → V3 0.510 → V4 0.480。**V4 反而最低。** |
| Ball AP50 | V4 最高（0.548），但靠精度换来的，召回下降 → 不是净收益 |
| **Racket Recall/AP50 是否提升** | V3 提升（0.679→0.727 / 0.735→0.738）；**V4 回落**（0.710 / 0.726），F1@0.25 从 0.758 掉到 0.669 |
| **Hand 是否退化** | 没有，V4 是三版里最好的（AP50 0.623、R 0.562） |
| 类别混淆 | V4 ball FN 中 DETECTED_OTHER_CLASS 从 6 降到 4，略有改善 |
| 推理耗时 | 三版同架构同输入，约 70–74 ms/帧（CPU，4 线程） |

## 4. 结论

- **V3 仍是 Ball + Racket 综合最优的候选**（ball F1 0.630 / racket F1 0.758）；
- **V4 不优于 V3**：ball AP50 略高但召回更低，racket 因注入自动框而退化；
  唯一亮点是 Hand 最好、overall mAP50 最高（0.632）。
- **按任务要求不替换 V3**。V4 权重与 ONNX 保留为实验记录，不进入交付包。
