# BALL_DATA_MINING_REPORT — 可靠小球样本挖掘

日期：2026-10-26

## 1. 结论先行

**本轮没有挖到新的可靠小球标注。** 现有可用数据已经被前几轮用尽，剩下的是"没有标签的原始视频"
和"置信度不足的模型候选"。按规则，这两者都不能直接充当 VERIFIED_GT。

因此 V5 的改进**不来自新增数据**，而来自一个可量化的训练变量：**输入分辨率 1280**
（依据见 `BALL_FN_DIAGNOSIS.md`：球在 960 输入下只有 9.6–16.9 px）。

## 4. 自动候选的处理（严格区分）

| 等级 | 数量 | 处理 |
| --- | ---: | --- |
| VERIFIED_GT | 0（本轮无新增） | — |
| AUTO_CANDIDATE | 0（未生成新候选） | — |
| NEEDS_REVIEW | 0 | — |
| REJECTED | 全部低置信预测 | 按"不得把低置信预测当真值"拒绝 |

**为什么没有生成新候选**：诊断已证明模型的低分球恰好就是困难球（19–24 px），
用它的低分输出做标签 = 把最不可靠的预测当监督信号，这正是 V4 在 racket 上犯过的错。
因此本轮**主动不做**这类伪标签挖掘。

## 5. 隔离与泄漏检查

- val（509 图）**未加入任何训练集**；本轮未改动 val 的任何标签。
- BNDSTT 球帧（`ps_*`）与 val 无重叠（文件名与来源均已核对）。
- 本轮 V5 训练用的数据 = V3 数据（`pingpong_unified_3cls_v4`），**与 V3 完全一致**，
  这样"分辨率"是唯一变量。

## 6. 下一轮要真正提升 Ball 的可行路径

1. **人工标注 300–500 个 19–24 px 的球**（从 BNDSTT 原始视频中抽帧，避开 val 来源）——
   这是唯一能直接提高小球密度且不引入噪声的办法；
2. 或**接受 1280 部署**（若 V5 证明有效），用算力换小球召回；
3. 不建议再做：伪标签注入、阈值下调冒充提升、在同一批数据上继续调参。
