# AI agent 协作指南

更新：2026-10-04。适用最新 AFH03 USB 同步双目方案。旧 H10/RK3566 交接包保存在[历史版本](../archive/routes/v2026-09-20_h10_rk3566/项目规划/Agent协作交接包.md)；现行角色和入口以本页、AGENTS.md 及最新个人分工为准。

## 先用通俗的话说明怎样开展任务

每个人把自己的职责文件交给 agent，并说明本次要完成哪一部分。agent 先检查现有文件和已经完成的成果，再把工作拆成能独立实现的小步骤，按依赖顺序持续完成。已有成果应接着使用，遇到一个缺少硬件的步骤时，先完成电脑上可以验证的部分，并把需要实物的接口和接手入口写清。

A 的 agent 主要把输入、图像保存、软件参考、硬件入口和整套程序接起来；B 的 agent 主要把图像中的球位置变成可解释的空间位置和发球过程；C 的 agent 主要准备数据、识别球手拍、输出可接入的模型，并独立核对系统结果。跨角色修改要说明对其他人的影响，任务归属和软件名称与个人文件一致。

电脑阶段主要使用 Windows 或 Linux、C++17、CMake、OpenCV、Python；FPGA 工作使用 Verilog、Icarus Verilog 和安路 TD；模型工作使用 PyTorch、RKNN-Toolkit2。记录实际安装版本和复现命令。没有板卡时先完成可迁移程序，拿到实物后逐层换入设备输入、板卡处理和推理运行环境。

把允许修改的目录、真实输入和要交付的东西写清即可。agent 应在授权范围内自主理解、实现和验证，直接修复能确定的问题；涉及未确定的共同接口或其他人的修改时，把具体影响整理成可评审的差异，参考相关负责人的技术复核建议，最终交蒲公英审批。GitHub 同步和合并也由蒲公英确认，用户已明确授权后不再额外要求其他队友批准。完成后交代码、配置、运行入口、实际结果和下一步入口，使用交接模板。

## 阅读顺序与当前依据

先读 [README](../README.md)、[当前方案索引](../plans/current/README.md)、[实施规划](../项目规划/项目实施规划.md)、[接口入口](../项目规划/接口与验收契约.md)、[待确认项](实施前待确认项.md)，再读[总分工](../项目规划/AFH03_USB同步双目方案一个月分工/00_三人分工与一个月实施安排.md)、对应个人说明第二部分、[PC 执行清单](PC算法闭环与部署验收.md)和[当前交接](../handoffs/README.md)。检查真实分支、提交号、工作区修改和已有实现，不能仅从旧对话或文件名推断状态。

正式目标是 AFH03 的 RK3576J + PH1A90SEG324，配 72°/3.6 mm 双 OV9281 USB3；YUY2 拼接 2560×720@60，每眼 1280×720。原图缓存保留 8 对，每眼搜索图 640×360；FPGA 返回 1 bit Mask，CPU 在同帧 256×256 ROI 内测量。H10 CK203 DDR3 是可选 RTL 参考平台，AFH03 的 DDR3L、PCIe1、资源与时序另验。上述参数沿用当前方案，本指南不改变协议、模型输入或判罚阈值。

截至本次文档同步，完整 PC 闭环、现行七级 RTL、模型训练与正式硬件部署仍待实施。已有 `fpga/rtl/afh03_image/` 是基础去噪/亮度/ROI 内核，历史测试报告可追溯，现行运动链路的验证另建记录。

## 三个角色的具体实现入口

**A：输入与系统。** 实现 `FrameSource`/`FileFrameSource`、YUY2 的 Y 提取、左右拆分、8 对原图缓存和 2×2 平均缩图；以 C++17/CMake/OpenCV 建可共用的运行核心。实现 `CpuMotionBackend` 的七级整数参考、异步完成/错误 mock，以及 FPGA 前三级 Gaussian、同眼帧差、阈值。负责 `PcieMotionBackend`、V4L2、DDR3L 与系统集成的后续适配。逐级输出与 B 的后四级和打包对照，保留 `reference_id` 与失败/复位语义。

**B：测量与事件。** 实现 FPGA 的腐蚀、膨胀、膨胀、腐蚀与 1 bit 打包；CPU 用 8 邻域连通域和原图 ROI 寻找球，按个人文件完成 64×64 Otsu、极性、闭运算、moments 和 Sobel。标定入口统一为 `findChessboardCornersSB`、`calibrateCamera`、`stereoCalibrate`、`stereoRectify`、`solvePnP`；点变换与三角测量使用 `undistortPoints`、`triangulatePoints`。校正三维先按 R1 的转置回左相机，再转换到 X 横向、Y 球台纵向、Z 向上的米制世界系。Kalman 使用真实采样 dt 和重力，最高点附近用预测 ROI 补测；发球状态与加权稳健最小二乘拟合按个人说明实现，证据不足保留 unknown。

**C：模型与独立评价。** 整理有许可的数据，按场次隔离训练、校准和测试，标注 `ball`、`hand`、`racket`。训练 YOLOv8n，先用实际 PC 模型从图像推理，`DetectionReplayBackend` 用于显式的下游对照；实现 `DetectorBackend` 与后续 `RknnDetectorBackend`。按当前 gray3/640×640/letterbox 114 预处理、一次归一化和坐标逆变换处理，适配 ONNX 输出、C++ DFL/NMS 与 RKNN-Toolkit2 的 `rk3576` 目标。总调用预算为 20～30 次/秒、左眼优先与右眼共享；训练和 Toolkit2 转换记录真实工具版本与状态。独立评分器读取 truth，报告每类检测、几何、事件和故障场景，结果不由被测程序自己的输出充当真值。

名称、具体参数和取整规则直接引用个人说明与[接口草案](../项目规划/接口与验收契约.md)。跨模块草案整理兼容影响并经蒲公英审批后再冻结字节布局；agent 不自行宣布完成联合评审，也不从旧 UDP 包或旧 v1.3 引用推导新 PCIe 协议。

## 代码目录与协作边界

`fpga/rtl/afh03_image/` 和 `fpga/sim/afh03_image/` 已有参考实现；`vision/train/`、`vision/quantize/`、`vision/calib/` 目前为开发入口。方案建议的 `software/pc_pipeline/`、`tools/fixtures/`、`tests/pc_pipeline/` 需在具体实现任务中创建，并由负责人与接口约定决定文件组织。

## 验证和交付

完成后至少交修改文件、构建/运行命令、输入来源与哈希、配置/工具版本、实际结果、失败/未执行项和下一位负责人的入口。日志分清 PC 软件、RTL 仿真、目标综合、RKNN 离线转换与真实设备结果。观测、滤波和预测分别记录；异步输出保留来源 `pair_id`，采样时间与完成时间分开。

truth、训练标签和独立评价输入隔离。合成双目由两台相机分别投影，公开或合成标定参数仅验证流程；最终米制参数由实物相机标定。真实三类模型模式与检测框回放模式分别报告，mock 调度不能充当 NPU 性能证据。

提交前运行仓库基础检查及本任务验证，检查差异后明确暂存文件。权重、视频、SDK、授权文件和生成工程继续留在被忽略的本地目录；用清单描述交付。按 [handoffs/TEMPLATE.md](../handoffs/TEMPLATE.md)书写交接，并更新对应现行入口。

以下通用提示词可与个人文件末尾的角色提示词一起使用：请先读取当前规则、技术路线、个人职责、接口草案和最新交接，核实分支、已有实现及工作区修改；在本次授权范围内自主拆解依赖并持续完成代码、配置和必要验证，保留可迁移的核心与真实数据来源。遇到缺少硬件或资料的步骤，先完成可独立验证的部分，记录确切阻塞和后续适配入口。涉及共同接口时给出兼容影响和可评审差异，保持草案状态，最终由蒲公英审批；交付真实运行入口、日志、输入与版本、未完成项和交接，不用计划或自述代替完成结果。
