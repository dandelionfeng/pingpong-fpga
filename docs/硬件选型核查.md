## 摄像头：芯片合适，不等于任意模组都能接

OV9281 的全局快门和高速输出适合运动测量，暂不建议为了更高像素更换传感器。真正需要买的是包含镜头、供电和接口的模组。两只应型号及镜头一致、可固定焦距并刚性安装，视野覆盖完整发球区域。[OMNIVISION 官方规格](https://www.ovt.com/products/ov9281/)。

**下单前由 A 与供应商确认五件事：**

1. 模组具体料号及版本；两路是否都能输出目标 1280×800@120fps、2-lane、RAW8。若实际只能输出 RAW10，B 的像素处理和 C 的模型输入约定需要重新评审，不能直接套用灰度 8bit 预算。
2. MLK-H10-PH1A180 两路 MIPI 的连接器针数、间距、正反面和引脚顺序，模组电源与控制电平是否匹配；是否需要转接板。
3. FSIN/XVS 等外触发引脚是否实际引出，电平、脉宽、极性及寄存器设置是什么。全局快门不等于两只相机自动同步。
4. 能否提供针对这块主板和这款模组的单目/双目采集工程、MIPI 接收 IP 使用条件、I2C 配置、引脚约束与 TD 版本。
5. 若两只相机使用相同 I2C 地址，例程如何分别配置；能否同时采集并区分左右图像。

**不能只看“OV9281”就下单。** 例如 Arducam 一款树莓派 OV9281 模组官方页面标注 1-lane 模式下全幅最高 60fps，说明模组实现会限制传感器能力；树莓派排线也不自动适配 H10。[该模组官方说明](https://www.arducam.com/arducam-ov9281-mipi-1mp-monochrome-global-shutter-camera-module-raspberry-pi.html)。

更推荐的是“板卡供应商确认过的双目全局快门套件 + 例程 + 排线”，而非单独追求更高级的传感器。若供应商只提供其他相机演示，可借其验证基础链路，但不能直接当作最终同步双目方案。USB OV9281 可用于 PC 算法采样，不作为当前 MIPI 前端的直接替换。

## 外接 NPU：实际买的是一台小型 Linux 计算机

连接方式为：FPGA 网口 — 网线 — 计算板网口，计算板单独供电，屏幕接计算板 HDMI。Linux 接收程序解析 ROI 后调用 NPU；不需要 FPGA 安装 RKNN 驱动。千兆网口和 UDP 程序匹配是通信条件，NPU 驱动、Runtime、模型转换版本匹配是推理条件。[瑞芯微 RKNN 官方支持列表与部署说明](https://github.com/airockchip/rknn-toolkit2)。

可比较的具体产品：

- **预算候选：Radxa ROCK 3C（RK3566，优先 2GB 版本）**。官方列有千兆网、HDMI 和 Linux 支持。适合先验证小模型；购买前确认提供带可用 NPU 驱动的系统及例程。规格有 1GB/2GB 两种，勿按通用 RK3566 参数假定内存或 CPU 频率。[官方产品说明](https://dl.radxa.com/rock3/docs/hw/3c/radxa_rock3c_product_brief.pdf)。
- **性能备选：Radxa ROCK 5B（RK3588，4GB 起评估）**。官方列出最高 6 TOPS NPU、2.5G 网口及显示接口，适合为双目检测、几何与界面留余量。连接 H10 时按共同支持的千兆链路验证；更快的单板网口不会提高 FPGA 端链路上限。[官方产品页](https://radxa.com/products/rock5/5b/)。

以上是基于官方接口资料的选型建议，尚未购买或实测，不是当前价格/库存承诺。不能从 TOPS 直接推出 3–5ms 延迟；120 对图像/秒等于 240 张 ROI/秒，需把预处理、推理、后处理和界面同时运行测一遍。升级 RK3588 时必须针对新目标重新转换模型并回归精度，不能直接复用 RK3566 的编译产物。
