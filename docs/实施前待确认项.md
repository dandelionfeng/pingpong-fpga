# 实施前待确认项

记录日期：2026-09-19。保留团队修改后的原文，本文件单独记录实施风险，不宣称完成硬件选型核验。

1. **板卡与算力**：以 PH1A180 + 双 OV9281 + RK3566 为当前方案；采购前核对具体板卡型号、FMC 引脚、MIPI 接收 IP、FSIN 接口、DDR 和网口例程。规划中的 RK3566 算力、2ms 单次推理、3–5ms 双目推理、DDR 吞吐与微秒级同步都需要官方资料或实测支撑，不能当作已验证指标。
2. **UDP 分包**：单目 128×128 灰度数据加 64 字节头为 16448 字节。普通 MTU 1500 的 IPv4/UDP 不能用两包直接承载它；依赖 IP 分片时，按无选项 IPv4 头计算约需 12 片。应先约定应用层分块大小、帧号、左右目标识、块号、重组超时、乱序/重复/丢包处理，再写 RTL 与接收端。不能以“永不丢帧”为保证。参考 [IPv4 标准 RFC 791](https://www.rfc-editor.org/rfc/rfc791)。
3. **头部字节布局**：契约中的 little-endian 数字 0x50494E47 对应字节 GNIP，与 ASCII PING 不同；须选择明确的线缆字节序。offset 0x38 的 u24 与 offset 0x3C 的 CRC 之间有一个字节空位，需明确填充及 CRC 范围。冻结时提供完整 64 字节黄金样例及交叉语言解析测试。
4. **带宽**：双目 128×128×120fps 的纯像素量是 3,932,160 B/s；每眼每帧加 64 字节头后是 3,947,520 B/s，尚未计算分块及网络开销。约 4.2 MB/s 是估算，不是吞吐测量。
5. **模型与几何**：明确灰度 uint8、归一化、INT8 scale/zero-point、ROI 左上角坐标、左右帧配对、标定版本和无效帧处理；防止 FPGA 与 RKNN 重复归一化。只传运动 ROI 是否足以识别离手、球丢失后的重捕获和界面全景显示，需用样例验证。
6. **判罚与延迟**：30°/35°等阈值须有需求依据；置信度不能替代测量不确定度或直接改变规则阈值。30ms 端到端等指标应定义起止时间并报告分位数、最坏值、样本量及漏检率。

建议第一项联调任务先冻结协议 v0.5 和黄金数据包，再开展 FPGA 发送端与 RK3566 接收端的并行实现。上述记录不擅自修改 v0.4 契约。
