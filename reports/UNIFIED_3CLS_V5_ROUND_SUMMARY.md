# 统一三分类 V5 轮 · 执行摘要

日期：2026-10-26　分支：`codex/c-pc-detector`　起点：`cc2a3ff`

## 结论

**V5（1280）训练完成但不达标：Ball Recall 从 0.460 跌到 0.370，"提高分辨率救小球"的假设被证伪。
不交付、不替换 V3。** 但拿到两个硬结论：① 小球漏检的物理原因已量化；② 1280 对 Racket 有明显的正面效果。

## 1. Ball FN 深度诊断（100 个 ball GT）

| 项目 | 结果 |
| --- | --- |
| GT 尺寸（原图 1920） | p10 19.2 / **p50 24.5** / p90 33.9 px |
| **换算到 960 输入** | p10 **9.6** / p50 **12.2** / p90 **16.9 px** |
| 换算到 1280 输入 | 12.8 / 16.3 / 22.6 px |
| FN 归因（V3, conf 0.25） | TOO_LOW_SCORE 34（64%）、NO_CANDIDATE 13、WRONG_CLASS 6、BAD_LOCALIZATION 0 |
| FN 归因（V5, conf 0.25） | TOO_LOW_SCORE 41、NO_CANDIDATE 24、WRONG_CLASS 4、BAD_LOCALIZATION 1 → **共 70 个** |
| 按尺寸（V5） | <19 px 6、**19–24 px 35**、25–34 px 21、35–49 px 8 |
| NMS 抑制 | **未发现**（NMS 类内，跨类不互抑；val 几乎每图 1 个球） |
| **val 标签完整性** | 高置信"无主球检测"仅 **2 个** → ball 漏标率 ≤2%，**排除标签问题** |

**五个问题的答案**：
1. 小球得分低是因为**在 960 输入下只有 9.6–16.9 px**（stride-8 特征图上 1.2–2 格）；
2. 降阈值有效但代价大：0.10 时 R 0.56 / P 0.59 / FP 0.08 每帧 —— **是工作点，不是模型提升**；
3. 有轻微球/背景与球/手混淆（6 个 FN 的 best overlap 是 hand/racket）；
4. 训练集小球密度不足且**分布偏大**（BNDSTT p50≈34 px vs val 24.5 px）；
5. 球 GT 基本无漏标（≤2%）。

## 2. Ball 数据挖掘

## 7. 关键未解决

1. **Ball Recall 的根因是尺度**（9.6–16.9 px @960），且**提高分辨率反而更差** →
   唯一可行路径是**人工补标 300–500 个 19–24 px 的小球**（现有数据已榨干）。
2. **Racket 标签缺口**仍需人工（自动手段全部实测有害）。
3. 无独立测试集、无 OV9281 真实域、无 RKNN/板端/C++ 实测。
