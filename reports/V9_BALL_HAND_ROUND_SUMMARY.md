# V9 双分类轮 · 执行摘要

日期：2026-10-30　分支：`codex/c-pc-detector`　起点：`d77d327`

## 结论

**真正的双分类模型训练出来了，但它比三分类的 V3 明显更差 —— Ball Recall 0.510 → 0.370。**
按验收线（Ball R ≥ 0.55）不通过，**不生成交付 ZIP，V3 保持唯一推荐模型。**

## 1. 双分类是否真正建立

**是，结构级证据**：

| 检查 | 结果 |
| --- | --- |
| 每个尺度 `cv3` 尾部卷积输出通道 | **[2, 2, 2]**（V3 是 [3,3,3]） |
| `nc` / `no` | **2** / **66**（V3 是 3 / 67） |
| 前向输出形状 | **(1, 6, 18900)**（V3 是 [1,7,18900]） |
| 保存后重载 | `nc=2, no=66, cv3 out=[2,2,2]` ✅ |
| 参数量 | 3,011,238（V3 3,011,433，仅少 195） |

Backbone / Neck / Box-DFL 分支 100% 复用；分类分支取 V3 的第 0（ball）、1（hand）通道，
racket 通道被真正删除。

## 2. 数据审计的两个硬发现

1. **只有 436 帧同时有 ball 和 hand 标注**（全部来自 BNDSTT `ps`）。
2. **V3 在 2,110 张 tabletennis 帧上检测不到任何手**（抽样 20 帧：0 个检测，最高分 0.000），
   所以"自动补 hand 标注"这条路**完全失效**——广角球台里的手在 960 输入下太小。

因为 ball 优先，最终采用**与 V3 完全相同的训练数据、只去掉 racket 标注**，
让"2 类 vs 3 类"成为唯一变量（详见 `V9_DATASET_AUDIT.md`）。

| 类别 | 指标 | V3 | **V9** | Δ |
| --- | --- | ---: | ---: | ---: |

## 5. 为什么反而更差

1. **监督信号少了 43.6%**：原数据 10,987 个框里 racket 占 4,790 个，去掉后每图正样本锐减；
2. **球与球拍空间强相关**：学"球拍"时顺带学到"球拍周边是目标区"，这条隐式上下文被删掉后，
   小球召回直接掉 12–15 点。

参数只少 195 个（cv3 是 1×1 卷积，每支只省 `C_in`），**所以"减类提速"在本模型上不成立**。
