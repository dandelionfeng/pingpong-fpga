# A 1.0.1 MJPEG 输入适配验证

日期：2026-10-12。基准 `fe7af549464b290b2573199a1cf5a00ebf4432a5`，任务分支 `codex/a-mjpeg-input-20261012`。蒲公英授权“适配MJPEG，其他设置不要改变；删除原版本并上传新版”。本次增加JPEG输入、V4L2格式协商及发布材料，未改原配置文件、GUI源码、七级算法、B/C接口数据结构或RTL。

## 实现与兼容范围

- 文件清单和截图包支持一帧一个2560×720 MJPG/MJPEG JPEG；直接灰度解码，检查编码尺寸、帧结尾、格式与16 MiB上限，支持中文路径和压缩文件SHA-256。
- Linux V4L2默认先请求原YUYV 2560×720@60，不满足时再请求MJPG同尺寸帧率；可显式选择格式。保留手动曝光、4缓冲、500 ms等待、内核采样时间/序号。按bytesused解码，失败后重新入队，坏帧不提交运动参考。
- 下游继续接收1280×720原眼GRAY8、640×360搜索图及原Mask/ROI；阈值12、取整、坐标、缓存、队列、检测预算和协议均未变。JPEG并不恢复未压缩相机原始Y真值。
- Windows保留文件/Qt回放，实时相机仍由Linux V4L2提供。未新增AVI等容器读取，也未接入B/C新分支。

## 复现入口

```powershell
tools/a_pipeline/build_windows.ps1 -DependenciesRoot 'C:\FPGA competition'
python tools/a_pipeline/generate_mjpeg_fixture.py --output output/mjpeg-new --pairs 125
build/a_pipeline_windows/pipeline_cli.exe --input output/mjpeg-new/manifest.json --output output/mjpeg-run
python tools/a_pipeline/verify_pixels.py --manifest output/mjpeg-new/manifest.json --run output/mjpeg-run --output output/mjpeg-pixels.json
build/a_pipeline_windows/pipeline_gui.exe --package output/mjpeg-new --self-test --output output/mjpeg-gui
```

Linux按现有`build_linux.sh`构建，Windows绝对清单先用`manifest_paths.py`映射。便携打包采用`package_release.py`，固定依赖和B/C接入规则见[软件说明](../software/pc_pipeline/README.md)。
